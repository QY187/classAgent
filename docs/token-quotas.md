# 用户每日大模型 Token 额度

更新时间：2026-11-02。本地实现，未部署线上；所有用户继续使用平台配置的 DeepSeek Key。

## 1. 产品规则

- 默认每人每天 **100,000 Token**，管理员与普通用户均受限制；管理员可为单个用户调整。
- 日界线为 **Asia/Shanghai，北京时间 00:00**。采用按日期分账，不依赖零点定时任务；昨日未用额度不结转。
- 统计大模型输入和输出 Token，包含意图识别、Agent 每轮模型选择/回答/修复、检索查询改写、纪要、小测，以及旧课程问答的普通和流式回答。
- **语音转写、向量化和重排不纳入这一版的大模型 Token 额度**，仍使用平台配置。此额度不能解释为平台全部 API 费用上限；这些服务后续应分别配置时长、调用或对应 Token 额度。
- Token 是使用单位，不是费用。不同模型、输入/输出或缓存价格可能不同，本次不折算人民币。历史监控数据不回填新账本，从功能启用后的调用开始计量。
- 用户从左侧导航「Token 额度」进入独立页面 `/quotas`，查看上限、已用、预留和当前可用量。管理员在该页面的「用户额度管理」搜索用户、调整额度、查询调用记录及核对未确认用量。个人设置保留账号资料与登录安全设置。
- 额度总览突出当前可用量，并用分布条区分已用、预留与可用额度；计量说明可按需展开。管理员点击「查看用量」后在居中弹窗查看调用时间、模型、用途、状态及 Token 明细，日期筛选、分页和人工核对均在弹窗内完成。支持 Esc、关闭按钮及点击遮罩关闭，关闭后恢复列表位置与触发按钮焦点；结算中阻止关闭。手机上的用户列表和调用记录采用卡片布局，详情内容在弹窗内滚动。
- 个人每日额度留空表示使用平台默认值，填 `0` 暂停新的模型调用。改额度不清空已用量，也不取消已经发出的调用；已有资料及回答仍可读取。

## 2. 调用与计量流程

```text
已认证业务用户 / 课次所属用户
  → 后端绑定用户级调用上下文
  → 每一次大模型调用前，独立事务检查并原子预留预算
  → 向供应商发送有输出长度限制的请求
  → 读取供应商 usage，独立事务幂等结算
  → 已用量增加，释放本次未使用的预留
```

额度并非只在聊天入口检查一次。多轮 Agent、格式修复及内部查询改写的每次外部模型请求均要重新预留，因此不能利用一次请求中的多次调用绕过额度。完成结果重放不发起模型请求，不重复收费；真正重试、修复或失败前已经发生的模型调用按实际用量记录。

预留输入预算使用完整消息、工具定义的 UTF-8 字节量及每项协议余量，输出采用请求中的 `max_tokens`。这是适用于当前文本模型接入的保守预算，**不是供应商 tokenizer 的精确计数**。实际结算仅来自供应商返回的有效非负整数用量，不把估算值冒充实际 Token。

现有 Agent 请求保持输出上限 2,500；原先没有显式上限的纪要、小测和旧课程问答在额度开启时统一设置 4,000。剩余额度不能覆盖保守输入及输出预算时会在发送前拒绝，即使它可能足够支付最终较短的回答；用户可减少上下文、次日再试或联系管理员调整。以后切换供应商、tokenizer 或输入模态，需要验证对应的预算策略。

`usage.total_tokens` 有效时使用总量；只有完整的输入/输出量时使用两者之和；完整分量与总量矛盾时不低于已知分量之和。只有部分字段且矛盾或没有可靠总量时保留为待核对。如果供应商实际报告超过预留，仍完整入账，后续调用被拦截，不截断账本或伪造更少的消耗。该机制控制新调用预算，不承诺异常供应商响应或管理员主动调整情况下平台费用严格等于额度。

## 3. 数据与并发

| 表 | 用途 |
| --- | --- |
| `user_token_quotas` | 按后端用户 ID 存储个人额度覆盖值，空值使用平台默认值 |
| `daily_token_usage` | 用户 ID + 北京日期联合主键，分别保存已用量及预留量 |
| `token_usage_entries` | 每个模型调用尝试的独立流水、模型、用途、归属日期、状态与供应商用量 |
| `token_quota_changes` | 管理员额度调整记录，包含调整人、调整前后值和时间 |

所有表由现有 API 启动建表流程幂等创建，不修改已有业务记录。新用户和存量用户无需提前创建额度行，第一次调用时惰性初始化；未调用用户也能看到默认额度。

预留事务锁定个人策略行，并执行带 `used + reserved + 本次预算 <= limit` 条件的原子 UPDATE，防止多进程同时超用。结算通过流水状态条件 UPDATE 防止重放，再以数据库表达式更新每日汇总，避免读改写丢失。预算与业务使用独立短事务，因此回答校验失败或业务结果回滚不会退还已经消耗的 Token。

凌晨前预留的调用在凌晨后结束，仍结算到调用开始的日期；新一天使用新行，不把旧预留移动到今天。数据库约束禁止已用量或预留量为负。

额度账本不依赖 `agent_traces`。监控记录允许写入失败、截断或缺报，不能用于强制配额扣减。额度数据库不可核对时则停止新的付费模型调用，并返回安全的失败原因。

## 4. 失败、取消和用量未知

| 情况 | 处理 |
| --- | --- |
| 剩余预算不足 | 发送前返回 `quota_exhausted`，无外部模型调用 |
| 缺少后端用户归属 | 返回 `quota_identity_required`，无外部模型调用 |
| 额度数据库不可用 | 返回 `quota_storage_unavailable`，不绕过扣减 |
| 供应商有实际用量，但回答格式或业务校验失败 | 仍记录供应商实际消耗 |
| 明确的请求拒绝，且没有实际用量 | 释放预留，例如认证、参数错误、限流 |
| 建连失败且尚未发送成功 | 释放预留 |
| 读取超时、HTTP 408、上游 5xx、缺少可靠 usage、流中断或用户取消 | 已发送则保留预留并标记待核对，不直接认定免费 |
| 进程被强杀 | 可能保留 `reserved`；不按时间自动退款，管理员可核对 |

正常流式请求开启 `stream_options.include_usage`，在最终用量片段中结算，包括 `choices=[]` 的用量片段。若调用尚未得到可靠用量，预留仍约束该用户后续调用，页面明确区分“已用”和“预留”。

管理员可为 `uncertain`，或创建已超过 15 分钟仍处于 `reserved` 的记录输入核对后的实际 Token 数。`0` 仅表示管理员确认没有消耗，不能把“暂时不知道”填为 `0`。操作保存核对管理员 ID，并只允许完成一次结算。核对前应确认调用已停止、检查供应商记录；超过 15 分钟只是人工排查条件，不代表自动确认失败。

对话中的超额错误复用现有失败卡片和历史保存机制，展示失败阶段、原因和请求编号；额度不足不会被当作普通查询改写故障悄悄降级，也不会被工具执行器转换为不明原因。

## 5. 用户身份与任务

聊天、小测、检索改写及旧课程问答入口从后端已经认证的用户名读取不可变用户 ID，再通过 `ContextVar` 绑定独立的调用上下文。用户不能在模型工具参数或请求体中选择扣谁的额度，线程结束后恢复上下文。

SSE 后台线程自行执行相同的用户绑定。后台纪要从课次所属课程取得 `owner_id` 再绑定，不依赖 HTTP 上下文，也不信任模型输出的用户信息。队列不传 API Key；仍由后端使用平台配置。

普通用户只能读取本人额度和流水。管理接口验证数据库里的 `users.role=admin`，不信任浏览器保存的角色。管理员也受默认每日额度约束，但修改额度及读取已有资料不调用模型。

## 6. API

| 接口 | 权限与用途 |
| --- | --- |
| `GET /quotas/me` | 当前用户今日额度、预留、已用、可用量及下一重置时间 |
| `GET /quotas/me/entries?day=YYYY-MM-DD&page=1` | 当前用户的指定日流水，每页 20 条 |
| `GET /quotas/admin/users?query=...&page=1` | 管理员搜索和分页查看用户额度 |
| `PUT /quotas/admin/users/{user_id}` | 管理员提交 `daily_limit`；整数 0–1,000,000,000 或 null 恢复默认 |
| `GET /quotas/admin/users/{user_id}/entries?day=...&page=1` | 管理员查询用户流水 |
| `PUT /quotas/admin/entries/{entry_id}/resolve` | 管理员输入核对后的 `actual_tokens` 完成待确认流水结算 |

配额写入 Schema 拒绝额外字段、负数、布尔值、非整数或越界值。所有数据只含必要标识、模型和计数，不保存提问、回答、供应商 Key 或响应正文。

## 7. 配置与启用

```dotenv
TOKEN_QUOTA_ENABLED=true
DAILY_TOKEN_LIMIT=100000
```

默认开启，未配置环境变量也使用每天 100,000 Token。根目录及 API 的 `.env.example` 已补充示例，本地 Compose 的 API 和 worker 均接入这两个变量；生产 Compose 原有 `env_file` 会传入设置。示例文件中的改动不会覆盖实际密钥。

改环境变量需重新创建相应容器，使 API 与 worker 配置一致；单个用户的额度调整则即时生效。生产发布需先让新 API 完成建表并通过健康检查，再启动加载新源码的后台 worker。关闭配额仅用于受控开发/测试，不应当作为数据库故障的自动回退。

现有业务单元测试隔离新增的额度数据库边界，额度专项测试显式开启真实账本；浏览器与 PostgreSQL 额外验证生产默认开启的真实调用链。完整验收记录在本地忽略目录 `test-results/token-quota-20261101/`，包含真实模型的调用计数以及测试账号清理结果。本轮未推送或部署线上。

## 8. 本地验证结果

- 后端全量：469 项测试和 12 项子测试通过，包含 29 项新增额度用例；6 条依赖与框架弃用警告。既有业务单测隔离额度数据库，不能将全量结果理解为每项都启用了额度。
- 前端：14 项测试通过；生产构建与类型检查通过。
- 真实 PostgreSQL：2 项验证通过。每日上限 1,000 时，12 路并发各预留 300，只允许 3 次成功；同一调用并发结算仅一次成功，汇总用量正确。
- 真实浏览器、API 和 PostgreSQL：5 项验证通过，覆盖本人读取、管理权限、单用户额度调整、真实 SSE 超额及历史原因、恢复额度重试和移动端展示，无页面运行错误。
- 真实模型联调：3 次模型请求共计 14,529 Token，最终预留为 0；完成结果重放未重复扣减。该数值仅代表本次验收消耗，不代表固定单次成本。
- 真实 Celery worker：1 项验证通过，零额度用户的后台纪要被阻止，失败原因保存且没有模型消耗扣减。
- 桌面及 390px 移动端页面已检查，无整页横向溢出；差异空白检查通过。临时验收数据按测试脚本清理。

以上为本地功能验收，不包含新的 RAG 质量评测或线上部署验收；语音转写、向量化和重排也未计入本次 Token 额度。
