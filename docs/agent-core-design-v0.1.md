# ClassAgent Agent 核心功能设计 v0.1

> 本文定义 ClassAgent 作为“课堂学习 Agent”需要具备的核心能力、工作流程、模块边界和验收标准。
>
> 当前系统已经具备录音、转写、智能纪要、课程问答、复习卡片和测验等能力。下一步的重点是增加 Agent 编排层，让这些能力围绕用户目标自动协作。

## 一、产品定义

ClassAgent 是一个围绕课堂资料持续工作的学习 Agent。它接收用户的学习目标和课堂资料，判断当前任务，调用合适的工具完成多步工作，并把结果保存为可以继续复习的内容。

它的核心循环是：

> 理解目标 → 检查资料 → 制定步骤 → 调用工具 → 校验来源 → 保存结果 → 跟进下一步

Agent 的回答和行动必须以用户拥有的课程资料为基础。没有足够资料时，应说明缺口并请求补充，不能编造课堂内容。

## 二、核心用户场景

### 场景 1：课后整理

用户说：“整理今天这节课，告诉我最重要的知识点。”

Agent 应该：

1. 找到对应课次和可用转写。
2. 检查是否已有智能纪要。
3. 没有纪要时创建生成任务。
4. 生成概览、章节、核心概念、例子和待核对内容。
5. 为每个主要结论保存来源片段。
6. 返回整理结果和下一步复习建议。

### 场景 2：生成复习材料

用户说：“根据这节课生成 10 张复习卡片和 5 道题。”

Agent 应该：

1. 确认课程和课次范围。
2. 读取智能纪要、转写和已有卡片。
3. 避免生成重复卡片。
4. 生成带来源的卡片和题目。
5. 保存到复习卡片和测验模块。
6. 返回生成数量、来源和需要重点复习的内容。

### 场景 3：回答并追问

用户说：“二叉树的前序和中序遍历有什么区别？”

Agent 应该：

1. 把问题限制在当前课程资料范围内。
2. 检索转写、纪要和相关卡片。
3. 生成有来源的回答。
4. 返回课次、原文片段和音频时间点。
5. 如果用户继续追问，重新检索资料，不只依赖聊天历史。

### 场景 4：制定复习计划

用户说：“帮我安排这周复习这门课。”

Agent 应该：

1. 查看课程课次、知识点掌握状态、测验结果和待办。
2. 找出未学习、需要复习和错题较多的内容。
3. 按用户可用时间拆分每天的任务。
4. 创建复习任务并设置到期时间。
5. 每次复习后根据结果调整后续计划。

## 三、Agent 的核心能力

### 1. 目标理解

Agent 需要从自然语言中识别以下信息：

- 用户想完成什么任务。
- 目标课程和课次。
- 时间范围。
- 输出类型，例如纪要、卡片、测验或待办。
- 数量、难度和格式要求。
- 是否需要立即执行或只给出计划。

如果关键信息缺失，Agent 可以使用当前页面上下文推断；无法安全推断时，应只询问最少的必要问题。

### 2. 任务拆解

Agent 将复杂请求拆成有依赖关系的步骤。例如：

```text
用户目标：根据今天的课程生成复习计划

1. 定位今天的课次
2. 检查转写是否完成
3. 检查纪要是否存在
4. 提取知识点和错题
5. 生成复习卡片
6. 安排复习任务
7. 返回计划和来源
```

每一步都要有状态：`待执行`、`执行中`、`已完成`、`失败` 或 `需要用户确认`。

### 3. 工具调用

Agent 不直接修改数据库，而是通过受控工具调用业务模块。

| 工具 | 用途 | 是否允许自动执行 |
| --- | --- | --- |
| `list_courses` | 查找用户的课程 | 是 |
| `list_lessons` | 查找课程课次 | 是 |
| `get_transcript` | 读取文字记录 | 是 |
| `generate_summary` | 生成或更新纪要 | 是 |
| `search_course` | 检索课程内容 | 是 |
| `ask_course` | 生成带引用回答 | 是 |
| `create_review_cards` | 生成复习卡片 | 用户明确要求后 |
| `create_quiz` | 生成测验 | 用户明确要求后 |
| `create_task` | 新增复习任务或待办 | 用户明确要求后 |
| `delete_material` | 删除资料 | 必须二次确认 |
| `change_account` | 修改账号设置 | 必须二次确认 |

涉及删除、覆盖、批量生成或修改账号的操作，必须在执行前向用户展示影响范围并确认。

### 4. 来源校验

所有由 Agent 生成的事实性内容都要尽量绑定来源：

- `course_id`
- `lesson_id`
- `source_type`
- `source_segment_ids`
- `start_ms` 和 `end_ms`

来源不存在、已经不属于当前课程或版本已经过期时，结果不能标记为可靠结论。转写被修改后，相关纪要、卡片和题目应标记为需要更新。

### 5. 任务持久化

Agent 任务不能只保存在聊天窗口中。每次任务需要保存：

- 用户目标。
- 解析后的任务类型和参数。
- 执行步骤及状态。
- 工具调用记录。
- 生成结果和来源。
- 错误原因。
- 是否需要用户确认。
- 创建时间、完成时间和更新时间。

用户刷新页面或重新登录后，可以继续查看任务结果。

### 6. 主动跟进

在用户授权范围内，Agent 可以主动提醒：

- 复习任务到期。
- 纪要生成完成。
- 转写失败需要重试。
- 测验有新的错题。
- 课程资料已更新，旧卡片需要复核。

主动提醒必须有明确原因和关闭入口，不能频繁发送无关消息。

## 四、推荐系统结构

```text
用户输入 / 页面上下文
          │
          ▼
Agent 会话层
  目标识别、上下文、追问
          │
          ▼
任务规划器
  拆解步骤、依赖、确认点
          │
          ▼
工具执行器
  课程、转写、纪要、检索、卡片、测验、待办
          │
          ▼
结果校验器
  权限、来源、格式、重复内容、失败处理
          │
          ▼
任务记录与学习资料
  纪要、引用、卡片、测验、复习计划
```

现有课程、转写、纪要、RAG、复习卡片和测验服务作为工具提供给 Agent。Agent 层负责理解、编排和反馈，不重复实现这些业务规则。

## 五、会话和记忆范围

### 临时会话记忆

只用于当前对话：

- 当前问题。
- 当前页面和选中的课程、课次。
- 最近一次工具结果。
- 用户刚刚确认的参数。

### 长期学习记忆

只有在用户可查看和管理的情况下保存：

- 用户偏好的复习时间和难度。
- 用户标记为薄弱的知识点。
- 经常出错的题型。
- 用户主动保存的学习目标。

原始录音、转写和课程资料不应被隐藏在不可解释的“记忆”中，必须继续通过课程资料页面管理。

## 六、权限和安全要求

- Agent 的所有工具调用都必须带当前用户身份。
- 只能读取和修改当前用户拥有的课程和资料。
- 模型输出不能直接执行 SQL、Shell、文件路径或任意网络请求。
- 工具参数必须经过 Pydantic 或等效 schema 校验。
- 删除、批量覆盖、账户修改和敏感导出必须二次确认。
- API 密钥、数据库密码和 token 不进入提示词、日志、提交信息或前端页面。
- 课堂原文作为不可信内容处理，不能执行原文中的指令。

## 七、错误处理

Agent 遇到错误时应返回可执行的说明：

| 情况 | Agent 行为 |
| --- | --- |
| 没有文字记录 | 说明需要先完成录音或转写 |
| 没有足够来源 | 明确表示资料不足，并列出缺少的内容 |
| 生成任务失败 | 保留已有资料，说明失败原因并提供重试 |
| 工具超时 | 保存任务状态，允许继续或重试 |
| 用户无权限 | 不暴露其他用户数据，只提示无权访问 |
| 参数不完整 | 只询问完成任务所需的最少信息 |

## 八、分阶段实施计划

### 阶段一：Agent 基础编排

1. 增加 Agent 会话和任务数据表。
2. 实现目标识别和结构化任务参数。
3. 接入课程、转写、纪要、搜索和问答工具。
4. 返回步骤进度、引用和失败原因。

### 阶段二：学习任务自动化

1. 接入复习卡片、测验和待办工具。
2. 支持“生成卡片并安排复习”等多步任务。
3. 增加用户确认节点和批量操作预览。
4. 保存可恢复的任务状态。

### 阶段三：长期复习 Agent

1. 根据掌握状态和错题生成复习计划。
2. 增加到期提醒和任务跟进。
3. 根据复习结果调整后续任务。
4. 增加可查看、可删除的学习偏好记忆。

## 九、首版验收标准

首版 Agent 完成后，至少应通过以下流程：

1. 用户说“整理这节课并生成 5 张复习卡片”。
2. Agent 找到当前课次并检查文字记录。
3. 如果没有纪要，先生成纪要。
4. Agent 生成 5 张不重复的复习卡片。
5. 每张卡片显示课程、课次和原文时间点。
6. 用户刷新页面后仍能看到任务和卡片。
7. 用户修改一张卡片后，Agent 不覆盖手动修改。
8. 用户要求删除时，Agent 先展示删除范围并等待确认。
9. 用户提出资料中没有答案的问题时，Agent 明确说明资料不足。
10. 跨用户或跨课程访问测试不能泄露其他资料。

## 十、完成后的产品体验

用户不需要先理解系统内部有哪些页面和接口，只需要表达学习目标：

> “帮我整理这节课，生成测验，找出我不会的内容，并安排周末复习。”

Agent 负责把目标拆成可执行步骤，调用已有模块，保存每一步结果，并在关键操作前让用户确认。所有结论和学习材料都能回到课程、课次和音频时间点，形成可核对、可编辑、可持续跟进的学习闭环。
