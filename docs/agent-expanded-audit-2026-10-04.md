## 1. 课程名包含关系导致误判范围（优先）

**真实模型流程 3/3 复现，受控测试同样复现。**

前提：本人同时拥有“数学”“高等数学”课程，当前对话绑定“高等数学”。

提问：“高等数学课程里，x²的导数是多少？”

实际回答：“当前对话限定在‘高等数学’。要查询‘数学’，请进入主对话或对应课程对话。”模型根本没有被调用；后端将“数学课程”匹配进“高等数学课程”。

定位：[范围检测](D:/Code/agentCode/classAgent/apps/api/app/modules/agent/loop.py:69)。

建议：先匹配完整、明确的课程名，处理重叠名称时按最长名称识别，不能对任意子串命中直接判定跨课程。

## 2. 原文核对混淆大小写，可能放过错误公式（优先）

**受控测试复现；没有据此宣称真实模型会主动犯同样错误。**

当前原文：“变量 X 与 x 是不同变量。”

模型结论：“变量 x 与 x 是不同变量。”

实际仍作为有效结论显示并附原文引用。原因是原文比较调用 `casefold()`，将大小写有数学含义的符号当作相同。

定位：[文本归一化](D:/Code/agentCode/classAgent/apps/api/app/modules/agent/claim_validation.py:6)。

建议：保留字母大小写，数学符号、数字、单位和代码标识符不能做有损归一化。继续采用保守原文回退，但增加公式及代码边界用例。

## 3. 结论可能附带不支持它的多余引用（中）

**受控测试复现。**

读取数据结构原文 E1 和高等数学原文 E2。结论“函数 f(x)=x² 的导数为2x”同时引用 `[E1,E2]`。

实际显示两个引用，第一个指向二叉树片段。结论确实由 E2 支持，但 E1 与结论无关。校验只检查结论能否在任意来源中找到，却保留模型列出的全部来源。

定位：[结论与来源核对](D:/Code/agentCode/classAgent/apps/api/app/modules/agent/claim_validation.py:30)、[引用生成](D:/Code/agentCode/classAgent/apps/api/app/modules/rag/service.py:104)。

建议：为每句结论返回实际支持它的来源集合，去掉无关编号；若多句话分别来自不同来源，按句分别标注。

## 4. 同条请求修改两个知识点，只完成第一个（中）

**真实模型流程 3/3 未完成第二个修改。**

请求：“把叶子节点标记为已掌握，再把前序遍历标记为未学习。”

数据库：只有一条 `update_knowledge_status` 回执，前序遍历仍为 `review`。首次回答只说明第一个成功，未说明第二项未执行；两次重复有说明“这条问题已经执行过该动作”。

当前设计明确规定每条问题最多修改一个知识点，这个限制本身是已有保护策略；问题是多目标请求没有统一识别并明确提示，容易让用户误以为整条任务已完成。

定位：[状态指令解析](D:/Code/agentCode/classAgent/apps/api/app/modules/chat/knowledge_actions.py:23)、[动作结果处理](D:/Code/agentCode/classAgent/apps/api/app/modules/agent/loop.py)。

建议：先统一提示每次只修改一个并要求选择目标，或在明确支持批量的产品决策后按不同目标记录独立动作；不要默默做其中一项。

## 5. 补课程名后，创建课程与添加课次的组合任务丢失（中）

**真实模型流程 3/3 未完成整个组合。**

对话：“创建课程，再添加第三讲。” → “线性代数”。

首次模型询问名称后只创建课程，没有第三讲；两次重复先尝试缺名称的创建、被后端拒绝，随后无法承接课程名，没有创建任何课程。作为对照，完整单条“创建线性代数课程，再添加第三讲”成功创建课程和课次。

定位：[创建指令补全](D:/Code/agentCode/classAgent/apps/api/app/modules/chat/course_actions.py:38)、[课次补全](D:/Code/agentCode/classAgent/apps/api/app/modules/chat/lesson_actions.py:17)、[澄清来源](D:/Code/agentCode/classAgent/apps/api/app/modules/chat/intents.py:24)。

建议：补全时保留原请求中的剩余明确操作和参数；工具缺参数拒绝也应转换成明确的待补字段说明。保留取消及咨询不能继承写授权的保护。

## 6. 创建课程时丢失明确学期（中，工具参数覆盖不足）

**真实模型流程 3/3 复现。**

请求：“创建线性代数课程，学期为2026秋。”

数据库中的课程已创建，`semester=None`；回答仅说明创建课程。业务创建服务支持学期，但 Agent 创建工具只有 `name` 参数，当前指令也没有提供后续修改学期的授权。

定位：[创建课程参数](D:/Code/agentCode/classAgent/apps/api/app/modules/agent/schemas.py:34)、[课程创建业务参数](D:/Code/agentCode/classAgent/apps/api/app/shared/schemas.py:6)、[创建执行](D:/Code/agentCode/classAgent/apps/api/app/modules/chat/course_actions.py)。

建议：扩展现有创建工具的学期字段，并严格核对用户明确给出的值；未给学期保持为空。不能通过让模型猜字段解决。

## 7. 组合查询完整性兜底仍有缺口（中）

**真实模型本轮两个场景正常完成；受控提前结束测试发现后端缺口。**

- “修改叶子节点状态，同时列出所有课程”：模型完成修改后提前结束，后端直接只显示修改回执，没有继续查询或标记目录查询未完成。
- “修改叶子节点状态，同时查询课程进度和未作答小测”：模型只查小测后结束，后端显示回执和小测，漏掉课程进度。分类只识别到 `workflow`，没有同时识别 `progress`。

定位：[查询要求识别](D:/Code/agentCode/classAgent/apps/api/app/modules/agent/answers.py:63)、[动作后补查询](D:/Code/agentCode/classAgent/apps/api/app/modules/agent/loop.py)。

建议：同一分句能识别多个查询类别，并加入课程目录；核对每项请求是否有本次结果，无法完成时分别说明。不要仅依据最后 JSON 判断任务完整。

## 8. 否定一个操作会把另一个明确操作一并禁用（较低）

**真实模型流程 3/3 复现。**

请求：“不要修改叶子节点，把前序遍历标记为已掌握。”

数据库完全未修改，安全性上没有越权。回答却说没有找到前序遍历，实际该知识点存在。整体否定识别禁用了全部写权限，模型对拒绝原因的说明也不准确。

定位：[整句取消检测](D:/Code/agentCode/classAgent/apps/api/app/modules/chat/intents.py:17)、[状态请求](D:/Code/agentCode/classAgent/apps/api/app/modules/chat/knowledge_actions.py:23)。

建议：区分否定目标和另一个明确的肯定操作，在无法可靠分辨时要求澄清，不能误报资料不存在。应在授权保护稳定后处理，不能为了提高执行率放松否定规则。

## 正常通过的扩展边界

- 取消创建后只回复课程名，没有重新创建；取消状态修改后只回复“已掌握”，没有恢复写入权限。
- 日期修改取消后再补年份，没有写入；2月30日补年份后也没有写入。
- 主对话给出课程、再补课次标题，正确保留日期并创建课次。
- 修改标题与日期一起缺少年份，补年份后两个字段正确更新。
- 第一次确认及再次确认知识点状态，没有重复写入。
- 全局对比两门课程能读取两边原文；保守回退后比较语言较弱，但没有编造内容。
- 不存在的红黑树主题和无依据的“所有二叉树叶子节点数量都是3”，没有输出错误事实。
- 原文读取后被修改，旧结论没有有效引用，返回资料不足。

## 建议处理顺序

1. 课程名重叠匹配、大小写敏感符号、多余引用支持关系。
2. 组合任务完整性：缺参数后保留原操作、识别多目标限制、识别全部查询。
3. 创建学期参数覆盖。
4. 分句的肯定和否定边界，并对拒绝原因准确说明。

- 每条问题仍只修改一个知识点。多目标请求统一先提示选择，避免静默完成第一项；未改变既有保护策略为批量修改。
