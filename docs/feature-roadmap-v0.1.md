# ClassAgent 后续功能规划 v0.1

> 基于《产品初版报告 v0.3》和当前技术验证版整理。
>
> 当前版本已经完成“课堂内容采集 → 转写 → 智能纪要 → 原文回溯 → 课程问答”的核心闭环。本文规划下一阶段要补充的学习和资料管理模块，不改变现有核心流程。

## 当前实施进度

- **复习卡片首版已在本地实现**：可以从纪要中有有效转写来源的核心概念生成卡片，也可以手动新增；支持编辑、删除、查看来源、标记掌握状态。重复提取不会覆盖已经编辑的卡片。
- **课程知识点清单已实现并推送**：汇总全部卡片，按课程及掌握状态筛选；用户看过后手动标记“未学习”“需要复习”或“已掌握”，不设置到期时间。
- **个人设置首版已实现**：课程归属和登录令牌使用稳定的用户 ID；设置页展示用户名，支持上传头像、修改密码。头像同步显示在侧边栏，用户名修改接口保留但设置页不展示。录音偏好和账号级数据管理尚未实现。
- **课程与课次管理已补齐**：支持编辑课程名称、学期、课次标题和日期；删除课程或课次前说明影响范围，并清理相关记录和文件。
- **课次资料管理已实现**：可按课次批量上传、查看、下载和删除 PDF、PPT、Word、图片及文本资料；课件内容尚未进入搜索和课程问答。
- **课堂小测首版已实现**：按课程或课次生成有原文依据的单选和判断题，生成后可核对、编辑标准答案；支持答题判分、历史成绩和错题加入知识点清单。AI 答案仍需用户核对。
- **全局搜索已扩展**：可搜索课程、课次、文字记录、智能纪要和知识点，并按课程、内容类型筛选；文字记录可定位到录音时间点，知识点可定位到具体卡片。
- 待办与疑问按用户当前决定暂缓；标记片段、课件内容检索和学习进度仍按下述规划后续接入。线上环境不在本次实施范围内。

## 一、规划目标

把 ClassAgent 从课堂资料记录工具扩展为课后复习工作台：

1. 自动把课堂内容转成可以复习的知识点、题目和待办。
2. 让学生知道今天该复习什么、哪些问题还没有解决。
3. 把录音、转写、纪要、课件和复习材料集中到课程资料库。
4. 用学习进度帮助学生了解课程掌握情况。

## 二、模块总览

| 优先级 | 模块 | 主要作用 | 依赖 |
| --- | --- | --- | --- |
| P0 | 知识点清单 | 按课程汇总知识点并手动标记掌握状态 | 复习卡片 |
| P0 | 复习卡片 | 将纪要和课堂内容转成知识点卡片 | 智能纪要、引用片段 |
| P0 | 待办与疑问 | 管理作业、待确认内容和没听懂的问题 | 智能纪要、手动标记 |
| P1 | 测验 | 根据课程内容生成练习题并记录结果 | 复习卡片、课程资料 |
| P1 | 资料库 | 统一管理课堂音频、文字、纪要和课件 | 课程、课次、文件 |
| P1 | 全局搜索 | 跨课程查找课堂内容和复习材料 | 搜索索引 |
| P2 | 学习进度 | 展示课程完成度、复习情况和学习时长 | 复习记录、播放记录 |
| P2 | 个人设置 | 管理账号、录音、AI 和数据设置 | 登录和权限 |

## 三、功能说明

### 1. 知识点清单

左侧导航提供“知识点清单”。页面按课程展示全部卡片：

- 默认展示全部课程，点开课程搜索框可从下拉列表选择，输入名称时下拉列表与知识点同步筛选。
- 按“未学习”“需要复习”“已掌握”筛选。
- 查看来源课次与原文片段。
- 看过卡片后手动修改状态，不自动安排复习日期。

待办、测验和疑问保留在各自模块中，后续可增加入口，不混入知识点清单。

**首版验收**：用户能看到自己所有课程的知识点；修改状态后列表立即更新；每张卡片都能跳回课程资料来源。

### 2. 复习卡片

复习卡片由智能纪要或用户手动创建，类型包括：

- 知识点：术语、定义和解释。
- 问答：问题、答案和来源。
- 公式或规则：表达式、适用条件和例子。
- 易错点：容易混淆的概念和纠正说明。

每张卡片保存课程、课次、来源片段、卡片内容和掌握状态。用户可以编辑、删除和手动新增卡片。

首版采用简单的三档状态：`未学习`、`需要复习`、`已掌握`。用户看过后自行选择状态，系统不按时间安排再次复习。

**首版验收**：一节已有纪要的课次可以生成卡片；卡片能显示引用并跳到转写时间点；用户修改状态后能在课程知识点清单中筛选。

### 3. 待办与疑问

待办模块统一管理课堂行动项：

- 作业和提交任务。
- 老师要求查找或准备的资料。
- 待向老师确认的问题。
- 学生标记的“没听懂”片段。

每条记录包含标题、详情、状态、截止时间、课程、课次、来源片段和备注。状态包括 `待处理`、`进行中`、`已完成` 和 `已忽略`。

智能纪要生成阶段可以提取作业和课堂问题，但用户必须能够修改提取结果，避免模型内容直接成为事实。

**首版验收**：用户可以手动新增、编辑、完成和删除待办；纪要中的作业和疑问可以一键加入列表；每条记录保留来源。

### 4. 测验

测验从指定课程或课次的资料生成，支持：

- 单选题。
- 判断题。
- 简答题。

题目、答案、解析和来源片段都需要保存。提交后显示得分和错题，错题可以转成复习卡片。

首版不追求复杂题库，先支持一次生成一组 5 到 10 题的章节小测。

**首版验收**：题目只能来自选定课程资料；每题有来源；提交后能看到结果；错题可以重新复习。

### 5. 资料库

资料库按课程和课次组织以下内容：

- 原始音频。
- 文字记录。
- 智能纪要。
- PDF、PPT、图片和其他课前资料。

用户需要能够上传、预览、下载和删除资料，并看到资料类型、大小、上传时间和处理状态。课堂原话与外部资料必须明确区分。

生产环境优先使用对象存储保存音频和附件，数据库只保存元数据和访问关系。

**首版验收**：资料可以归属到课程或课次；上传失败不影响已有录音；删除前有确认；下载文件内容与上传内容一致。

### 6. 全局搜索

在现有搜索基础上扩展到所有用户可访问的资料：

- 课程名称和课次标题。
- 转写正文。
- 智能纪要。
- 复习卡片。
- 待办和疑问。
- 课件文字内容。

结果必须显示类型、所属课程、课次和匹配位置。点击结果后跳转到对应页面或音频时间点。

**首版验收**：跨课程搜索不会混入其他用户数据；结果可以按类型和课程筛选；转写结果能定位到时间点。

### 7. 学习进度

学习进度页面按课程提供：

- 已完成课次和未完成课次。
- 已生成纪要的课次。
- 复习卡片总量、需要复习数量和已掌握数量。
- 测验次数、平均得分和错题数量。
- 录音和复习时长。

首版只展示可解释的统计数据，不根据单次测验分数推断能力等级。

**首版验收**：统计范围可以切换课程和日期；数据与实际课次、卡片和测验记录一致；空数据时有明确空状态。

### 8. 个人设置

设置模块包括：

- 用户名和登录安全。
- 默认录音和上传偏好。
- AI 服务状态和模型配置提示。
- 数据导出和账户数据删除。

密钥只保存在服务端环境变量中，前端不展示密钥内容。涉及删除账户、课程和音频的操作需要二次确认。

## 四、建议实施顺序

### 阶段一：复习基础

1. 设计 `review_cards`、`tasks` 和 `questions` 数据表。
2. 从智能纪要中提取卡片、作业和疑问。
3. 完成复习卡片页面和待办页面。
4. 增加按课程聚合的知识点清单。

### 阶段二：练习与资料

1. 增加测验生成、答题和错题记录。
2. 增加附件模型和资料库页面。
3. 将附件内容纳入课程问答检索，并标注来源类型。

### 阶段三：检索与数据反馈

1. 扩展全局搜索索引。
2. 增加学习进度统计。
3. 增加播放、复习和测验行为记录。

### 阶段四：生产完善

1. 音频和附件迁移到对象存储。
2. 增加数据库、音频和附件备份。
3. 增加任务监控、失败告警和审计日志。
4. 绑定正式域名并完善 HTTPS 与账号安全策略。

## 五、通用数据和可信度要求

- 每条卡片、题目、待办和疑问都要保存课程、课次和来源片段。
- 模型生成内容必须标注来源；无法确认时标记为“待核对”。
- 课堂录音、课堂转写和外部课件在界面上使用不同来源标签。
- 删除课次或资料时，必须同步处理相关索引、卡片、题目和引用关系。
- 用户只能访问自己拥有的课程和资料。
- 任何生成任务都要保留状态、失败原因和可重试入口。

## 六、完成标准

下一阶段完成后，用户应能完成这条路径：

> 录音或上传课堂 → 查看转写和智能纪要 → 生成知识点卡片与测验 → 在知识点清单中手动标记掌握状态 → 处理作业和疑问 → 回到原文核对依据。

每个学习结论、卡片、题目和任务都能回到对应课程、课次和时间点，保证复习内容可核对、可编辑、可导出。
