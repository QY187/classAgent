# ClassAgent Agent 技术路线

> 文档状态：核心流程已实现，持续完善中
> 更新时间：2026-10-15

## 1. 背景与目标

ClassAgent 使用 Agent 统一处理课程查询、课堂检索、课程管理、转写任务、学习记录和小测等操作。用户用自然语言表达需求，Agent 选择工具，后端完成参数、权限和业务校验。

目标：

- 让用户通过自然语言完成查询和课程操作；
- 支持单工具和多工具编排；
- 工具调用必须受到后端权限和业务规则约束；
- 读操作返回真实数据，写操作返回真实回执；
- 支持澄清、重试、失败降级和死循环保护；
- 在课堂问题中接入 RAG，并保证答案有证据引用。

## 2. 设计原则

1. **模型负责理解和选择，后端负责执行**：模型不能直接修改数据库或绕过权限。
2. **工具优先于模型猜测**：课程、课次、状态、成绩和检索结果必须通过工具获取。
3. **写操作明确授权**：用户未明确要求时不能创建、修改或重试。
4. **结果必须可核验**：最终答案使用工具实际返回的数据，不能使用模型编造的 ID、数量和状态。
5. **范围始终绑定用户会话**：课程对话和课次对话不能越过后端绑定范围。
6. **循环有上限，失败可恢复**：限制轮次、调用次数和总时长，外部服务失败时按策略降级。

## 3. 总体架构

```text
┌──────────────┐
│ 用户消息      │
└──────┬───────┘
       │
┌──────▼─────────────────┐
│ 会话/用户/课程范围校验  │
└──────┬─────────────────┘
       │
┌──────▼─────────────────┐
│ 规则预处理和写意图检查  │
└──────┬─────────────────┘
       │
┌──────▼─────────────────┐
│ 大模型 + 工具 Schema    │
│ 意图理解和工具选择      │
└──────┬─────────────────┘
       │ tool_calls
┌──────▼─────────────────┐
│ 参数校验/权限/业务校验   │
└──────┬─────────────────┘
       │
┌──────▼─────────────────┐
│ 工具执行器和业务 Service │
└──────┬─────────────────┘
       │ tool result
┌──────▼─────────────────┐
│ Agent 循环继续/澄清/结束 │
└──────┬─────────────────┘
       │
┌──────▼─────────────────┐
│ 最终结果、引用和回执校验 │
└────────────────────────┘
```

核心实现：

- `apps/api/app/modules/agent/loop.py`：Agent 主循环；
- `apps/api/app/modules/agent/registry.py`：工具注册和 Schema；
- `apps/api/app/modules/agent/executor.py`：工具解析、校验和执行；
- `apps/api/app/modules/agent/tools.py`：工具实现；
- `apps/api/app/modules/agent/responses.py`：最终结构化响应解析；
- `apps/api/app/modules/chat/`：会话、语义预处理、写操作和消息持久化。

## 4. 一次请求的完整流程

```text
用户输入
→ 校验问题长度和会话身份
→ 加载当前用户和会话范围
→ 规则识别明确写操作
→ 构造系统约束、历史和工具 Schema
→ 调用大模型
→ 判断是否产生 tool_calls
→ 后端校验并执行工具
→ 将 tool result 回传大模型
→ 继续调用、请求澄清或生成最终 JSON
→ 后端重新核验结果
→ 返回答案、步骤、引用或操作回执
```

当前主循环使用以下限制：

```text
MAX_ROUNDS = 6
MAX_CALLS = 8
MAX_SECONDS = 90
```

达到任一限制后，Agent 停止继续调用，避免模型陷入循环或持续消耗外部资源。

## 5. 输入和会话范围

每个 Agent 请求由后端绑定：

- 当前用户；
- 当前会话；
- 可选课程 ID；
- 可选课次 ID；
- 当前用户可用的写操作集合；
- 对话历史。

课程对话默认限制在当前课程，课次对话默认限制在当前课次。用户在课程对话中询问其他课程时，Agent 不会擅自切换范围，而是提示进入主对话或对应课程。

历史消息只用于理解指代，不自动提供事实依据，也不能从历史消息继承写操作授权。

## 6. 意图识别方式

当前采用“规则预处理 + 大模型工具选择 + 后端校验”，没有把所有逻辑放在单独的固定分类器中。

### 6.1 规则预处理

规则主要处理高风险或必须补充参数的场景：

- 创建课程；
- 创建课次；
- 修改课程或课次；
- 重试转写；
- 修改知识点状态；
- 生成小测。

规则检查是否有明确操作动词、目标是否唯一、必要字段是否缺失，以及当前会话是否允许操作。缺少课程名称、课次标题或日期时，直接返回澄清问题，不让模型猜测。

### 6.2 大模型工具选择

模型输入包含系统约束、用户问题、历史、范围和工具 Schema。

模型可以选择：

- 直接回答；
- 调用一个工具；
- 同时调用多个独立工具；
- 先查询再执行依赖工具；
- 返回 `needs_input` 请求澄清。

工具定义说明用途、参数和限制，模型只负责选择，不拥有数据库权限。

## 7. 工具注册和执行

### 7.1 工具注册

每个工具在注册表中包含：

```text
name
description
arguments schema
handler
writes
```

根据当前上下文，系统只把允许的工具 Schema 提供给模型。未授权的写工具不会出现在当前 Agent 的工具列表中。

### 7.2 工具执行器

模型产生调用后，执行器按以下顺序处理：

```text
解析工具名称
→ 查找注册定义
→ 校验 JSON 参数
→ 执行范围校验
→ 执行业务 Handler
→ 转换为结构化结果
```

未知工具、参数错误、业务错误和权限错误都会转换为结构化失败结果，模型不能把失败结果说成成功。

### 7.3 常用工具

当前工具覆盖：

- `list_courses`：查询当前用户课程；
- `list_lessons`：查询课程课次；
- `get_transcript`：分页读取逐字稿；
- `get_summary`：读取纪要及状态；
- `search_course`：搜索课堂内容并返回时间和来源；
- `get_processing_detail`：查询课次处理状态；
- `retry_transcription`：登记失败转写重试；
- `create_course`、`create_lesson`：创建课程和课次；
- `update_course`、`update_lesson`：修改课程和课次；
- `generate_quiz`：生成课程小测；
- `generate_practice_quiz`：基于学习记录生成练习；
- `list_knowledge_points`、`update_knowledge_status`：查询和修改知识点状态；
- 学习进度、错题和小测成绩查询工具。

## 8. 单工具和多工具编排

### 8.1 单工具

```text
用户：列出我的课程
→ list_courses
→ 返回真实课程列表
```

### 8.2 查询后再执行

```text
用户：给数据结构课程添加第三讲
→ list_courses 定位唯一课程
→ list_lessons 检查同名课次
→ create_lesson
→ 返回真实创建结果
```

### 8.3 多个独立查询

```text
用户：告诉我课程进度，并列出还没做的小测
→ get_course_progress
→ list_unanswered_quizzes
→ 合并两个真实查询结果
```

### 8.4 部分成功

如果一条消息包含多个操作，其中一个成功、另一个失败，最终答案必须分别说明实际结果，不能用“全部完成”概括。

依赖链中的前一步失败时，后一步不能继续执行。例如无法唯一定位课程时，不允许直接创建课次。

## 9. 写操作和幂等

写操作包括创建、修改、重试、更新知识点状态和生成小测。流程是：

```text
明确用户请求
→ 目标唯一性检查
→ 参数和范围校验
→ 权限校验
→ 幂等键检查
→ 数据库事务
→ 保存 AgentAction 回执
→ 真实结果返回
```

写操作要求：

- 不从课堂文本或历史消息继承授权；
- 不猜测课程、课次、日期或标题；
- 同一消息重复执行不能产生重复数据；
- 已经完成或正在处理的任务不能重复提交；
- 成功、失败和部分成功都必须如实返回。

## 10. Agent 与 RAG 的关系

Agent 不直接实现向量检索，而是通过 `search_course` 或问答流程接入 RAG。

```text
Agent 判断用户要查询课堂内容
→ 调用 search_course 或课程问答
→ RAG 查询改写
→ BM25 + 向量召回
→ RRF 融合
→ Cross-Encoder 重排
→ 父块扩展
→ 返回证据
→ Agent 组织最终答案
```

RAG 返回的子块、父块、课次、时间和来源 ID 都属于工具证据。Agent 不能自己编造课堂结论或引用编号。

## 11. 最终响应格式和证据校验

Agent 最终使用结构化 JSON，常见结果类型包括：

```json
{
  "claims": [
    {"text": "课堂结论", "source_ids": ["E1"]}
  ]
}
```

需要澄清时：

```json
{
  "outcome": "needs_input",
  "question": "请提供课程名称",
  "claims": []
}
```

资料不足时：

```json
{
  "outcome": "insufficient_evidence",
  "claims": []
}
```

后端解析结果时校验：

- JSON 结构是否合法；
- claim 是否有文本；
- source ID 是否属于本次证据；
- 工具结果是否真实存在；
- 查询编号是否来自本次实际查询；
- 写操作是否有真实回执。

## 12. 死循环和异常处理

### 12.1 死循环控制

通过轮数、调用次数和总时长限制控制循环。对重复工具调用，Agent 应优先修正参数或向用户澄清，而不是无限重复。

### 12.2 工具异常

工具失败返回结构化错误。模型需要根据真实错误决定澄清、重试或结束，不能伪造成功。

### 12.3 大模型异常

模型超时、输出非法 JSON 或产生不允许的工具调用时，系统返回可控错误，并保留消息和执行状态，避免用户看到不确定的业务结果。

### 12.4 外部任务异常

转写、摘要和索引等异步任务通过状态记录进度。重试任务要求当前课次确实处于失败状态，已有文字时不会清空原内容，也不会把“已登记重试”说成“已经完成”。

## 13. 权限与安全

权限校验分布在多个层次：

```text
会话范围
→ 工具是否可见
→ 课程/课次归属
→ 工具参数校验
→ Service 数据查询
→ 最终引用和回执校验
```

课堂逐字稿、摘要和工具结果都视为不可信输入，不能执行其中的提示词或命令。用户消息中的明确授权优先于课堂文本，但仍不能越过后端权限。

写操作还需要防止：

- 模型添加未允许的字段；
- 用户通过自然语言修改他人课程；
- 重复提交任务；
- 利用历史消息伪造当前授权；
- 工具返回结果被模型篡改。

## 14. 可观测性和执行记录

每次请求记录：

- 用户、会话、课程和课次范围；
- 原始问题和历史摘要；
- 模型版本和 Prompt 版本；
- 工具选择和参数；
- 每个工具的开始、结束和耗时；
- 成功、失败和降级原因；
- 最终 claims、引用和操作回执；
- 总 token、模型耗时和数据库耗时。

工具步骤通过进度状态返回，写操作通过 `AgentAction` 保存，便于幂等、审计和问题排查。

## 15. 测试和质量评估

Agent 测试分为：

### 15.1 意图和工具选择

- 查询是否选择正确工具；
- 多意图是否调用多个工具；
- 缺少参数是否澄清；
- 明确否定是否不执行写操作。

### 15.2 工具和权限

- 参数非法是否被拒绝；
- 他人课程是否不可见；
- 当前课程范围是否不能越界；
- 重复消息是否幂等；
- 工具失败是否如实返回。

### 15.3 RAG 和答案

- 课次 Recall；
- 子块 Recall@K；
- 父块证据覆盖率；
- 引用准确率；
- 答案要点覆盖率；
- 资料不足时是否拒答。

### 15.4 系统指标

- 首字节和完整响应延迟；
- 工具调用次数；
- 循环终止率；
- 模型和工具错误率；
- 降级率；
- token 和单次请求成本。

## 16. 当前实现与企业级演进

已实现：

- 模型驱动的工具选择；
- 工具注册、Schema 和后端执行器；
- 多工具循环；
- 参数、权限和业务校验；
- 写操作幂等和真实回执；
- RAG 混合召回和证据引用；
- 死循环限制和外部服务降级。

后续可以演进：

1. 增加轻量意图路由器，先区分查询、写操作、闲聊和澄清；
2. 使用持久化状态机或工作流引擎支持暂停、恢复和审批；
3. 增加统一 Trace，串联模型、工具、数据库和 RAG；
4. 增加 Prompt、工具 Schema 和模型版本管理；
5. 增加线上用户反馈和 Agent 成功率评测；
6. 增加限流、缓存、熔断和多模型路由。

## 17. 技术路线总结

ClassAgent 当前采用“模型理解、工具执行、后端裁决”的 Agent 架构：

```text
自然语言输入
→ 范围和授权校验
→ 规则预处理
→ 大模型选择工具
→ 后端验证并执行
→ 工具结果回传
→ 受限循环编排
→ 证据/回执校验
→ 最终答案或操作结果
```

这种设计让大模型负责处理自然语言和任务编排，让后端负责权限、数据一致性和业务真实性，适合继续扩展课程管理、学习记录、RAG 问答和练习生成能力。
