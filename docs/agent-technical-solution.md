# ClassAgent Agent 技术路线

> 文档状态：核心流程已实现，持续完善中
> 更新时间：2026-11-01

## 1. 背景与目标

ClassAgent 使用 Agent 统一处理课程查询、课堂检索、课程管理、转写任务、学习记录和小测等操作。用户用自然语言表达需求，Agent 选择工具，后端完成参数、权限和业务校验。

目标：

- 让用户通过自然语言完成查询和课程操作；
- 支持单工具和多工具编排；
- 工具调用必须受到后端权限和业务规则约束；
- 读操作返回真实数据，写操作返回真实回执；
- 支持澄清、重试、失败降级和死循环保护；
- 在课堂问题中接入 RAG，并保证答案有证据引用。

## 2. 设计原则

1. **模型负责理解和选择，后端负责执行**：模型不能直接修改数据库或绕过权限。
2. **工具优先于模型猜测**：课程、课次、状态、成绩和检索结果必须通过工具获取。
3. **写操作明确授权**：用户未明确要求时不能创建、修改或重试。
4. **结果必须可核验**：最终答案使用工具实际返回的数据，不能使用模型编造的 ID、数量和状态。
5. **范围始终绑定用户会话**：课程对话和课次对话不能越过后端绑定范围。
6. **循环有上限，失败可恢复**：限制轮次、调用次数和总时长，外部服务失败时按策略降级。

## 4. 一次请求的完整流程

```text
用户输入
→ 校验问题长度和会话身份
→ 加载当前用户和会话范围
→ 保存请求快照并加载有效待办
→ 大模型将本轮输入解析为结构化计划
→ 校验计划类型、必填字段、日期来源和续接关系
→ 保存已验证计划，按计划开放写工具
→ 缺少参数则保存待办并澄清；取消则结束待办
→ 构造执行阶段的系统约束、历史和工具 Schema
→ 大模型选择工具
→ 判断是否产生 tool_calls
→ 后端校验并执行工具
→ 将 tool result 回传大模型
→ 继续调用、请求澄清或生成最终 JSON
→ 后端重新核验结果
→ 返回答案、步骤、引用或操作回执
```

当前主循环使用以下限制：

```text
MAX_ROUNDS = 6
MAX_CALLS = 8
MAX_SECONDS = 90
```

上述限制属于工具执行循环。语义规划另有 20 秒预算，单次调用最多 15 秒，格式校验失败至多修复一次。两阶段预算分开计算，不应把 90 秒理解为完整 HTTP 请求的绝对时限。

## 5. 输入和会话范围

每个 Agent 请求由后端绑定：

- 当前用户；
- 当前会话；
- 可选课程 ID；
- 可选课次 ID；
- 当前用户可用的写操作集合；
- 对话历史。

课程对话默认限制在当前课程，课次对话默认限制在当前课次。用户在课程对话中询问其他课程时，Agent 不会擅自切换范围，而是提示进入主对话或对应课程。

规划阶段不读取普通聊天历史，只接收当前输入、后端有效待办、绑定范围和可见实体名称。执行阶段仍接收最近历史帮助理解查询，但不能借此增加写权限；写权限只来自本轮已校验计划。

## 6. 意图识别方式

当前采用“每轮语义规划 → 类型契约校验 → 有状态续接 → 授权工具执行”。不先用关键词判断用户是否想操作，也不在模型失败时用正则猜测写权限。

### 6.1 语义规划

每条消息，包括读取、闲聊和补充参数，均进入规划器。模型返回 `TurnDecision`：

| 字段 | 含义 |
| --- | --- |
| `relation` | `new` 新请求、`continue` 补充待办、`cancel` 取消待办 |
| `task_id` | 续接时必须匹配后端有效待办；其他情况为空 |
| `intent` | 创建、修改、重试、出题、核验及读取要求 |
| `clarification` | 缺失信息的澄清问题 |
| `date_source` | 用户当前输入或有效待办中的日期原文 |

例如“把第一讲挪到明天”由模型识别为修改课次日期；“考我三道判断题”识别为出题，保留题量和题型。后端不要求出现固定的“修改”“生成”关键词。

为了减少名称误解，规划器获得当前用户可见的实体名称：主对话提供课程，绑定课程后还提供课次和知识点。每类最多 30 条，并标注是否截断；这些只是定位提示，最终目标仍须通过工具查询，未出现在提示中不代表不存在。

### 6.2 契约与参数校验

Pydantic 使用严格类型并禁止额外字段，校验动作是否兼容、修改字段是否支持、续接任务是否有效，以及是否重新加入已成功动作。格式不合法时将具体错误交给模型修复一次；仍失败则返回解析错误，不执行本轮新增操作。

在绑定课程内，若创建计划与可见的已有课次同名，后端把实体冲突交给模型复核一次。模型根据原句区分“给已有课次安排日期”和“新建课次”；后端不把创建自动改写成修改。明确想再建同名课次时先澄清，避免一句“第一讲就排在明天吧”误建重复课次。

必填信息由后端决定：课程名称、课次标题和修改字段等不能猜；学期、创建课次日期是可选信息，不能因为缺少它们而反复追问。小测明确题量、题型、课程和课次在实际生成前再次核对，防止执行模型改掉用户要求。

日期处理属于参数归一化，不是意图识别。模型必须提取日期原文，后端验证其确实来自授权输入，再计算“明天”“下周一”等日期；只有月日时不擅自补年份，后续单独补充年份可与有效待办合并。不能可靠解析的日期继续澄清。

### 6.3 待办生命周期

待办保存在 `ChatConversation.pending_task_json`，请求输入和已验证计划保存在 `ChatMessage.intent_state_json`。

```text
新请求 → 规划并校验 → 信息完整 → 执行 → 回执核验 → 结束
                      信息缺失 → 保存待办 → 下一轮补充 → 再校验
                      取消/换话题 → 清除旧待办
```

- 待办绑定用户、会话、课程和课次，只能承接紧邻的澄清回合。
- 从首次澄清起 30 分钟有效，最多保留 4 轮澄清，不通过不断补参无限续期。
- 新请求先消费会话待办，并保存请求快照；取消、换话题、成功完成后不残留旧写权限。
- 续接只允许原待办的未完成动作，已成功部分依据数据库回执扣除。
- 同一请求失败后重试复用已验证计划，结合原有写幂等机制避免模型重新判断导致动作变化。
- 普通工具失败不自动变成可续接任务；需要用户补参的结果才保存为待办。

“取消后又发一个日期”或“操作成功后说好的”不会仅凭旧聊天命令重新执行写入。

### 6.4 大模型工具选择

执行模型接收系统约束、当前问题、最近历史、绑定范围、计划参数及允许的工具 Schema。

模型可以选择：

- 直接回答；
- 调用一个工具；
- 在同一轮输出多个独立工具调用；
- 先查询再执行依赖工具；
- 返回 `needs_input` 请求澄清。

工具定义说明用途、参数和限制，模型只负责选择，不拥有数据库权限。

当前执行器逐个执行同轮调用，不等同于并行数据库写入。每条消息增加一次语义规划调用，是换取自然表达理解、参数持久化和明确授权边界的成本；尚未实现规划缓存或轻量模型分流。

## 7. 工具注册和执行

### 7.1 工具注册

每个工具在注册表中包含：

```text
name
description
arguments schema
handler
writes
```

根据当前上下文，系统只把允许的工具 Schema 提供给模型。未授权的写工具不会出现在当前 Agent 的工具列表中。

### 7.2 工具执行器

模型产生调用后，执行器按以下顺序处理：

```text
解析工具名称
→ 查找注册定义
→ 校验 JSON 参数
→ 执行范围校验
→ 执行业务 Handler
→ 转换为结构化结果
```

未知工具、参数错误、业务错误和权限错误都会转换为结构化失败结果，模型不能把失败结果说成成功。

### 7.3 常用工具

当前工具覆盖：

- `list_courses`：查询当前用户课程；
- `list_lessons`：查询课程课次；
- `get_transcript`：分页读取逐字稿；
- `get_summary`：读取纪要及状态；
- `search_course`：搜索课堂内容并返回时间和来源；
- `get_processing_detail`：查询课次处理状态；
- `retry_transcription`：登记失败转写重试；
- `create_course`、`create_lesson`：创建课程和课次；
- `update_course`、`update_lesson`：修改课程和课次；
- `generate_quiz`：生成课程小测；
- `generate_practice_quiz`：基于学习记录生成练习；
- `list_knowledge_points`、`update_knowledge_status`：查询和修改知识点状态；
- 学习进度、错题和小测成绩查询工具。

## 8. 单工具和多工具编排

### 8.1 单工具

```text
用户：列出我的课程
→ list_courses
→ 返回真实课程列表
```

### 8.2 查询后再执行

```text
用户：给数据结构课程添加第三讲
→ list_courses 定位唯一课程
→ list_lessons 检查同名课次
→ create_lesson
→ 返回真实创建结果
```

### 8.3 多个独立查询

```text
用户：告诉我课程进度，并列出还没做的小测
→ get_course_progress
→ list_unanswered_quizzes
→ 合并两个真实查询结果
```

### 8.4 部分成功

如果一条消息包含多个操作，其中一个成功、另一个失败，最终答案必须分别说明实际结果，不能用“全部完成”概括。

依赖链中的前一步失败时，后一步不能继续执行。例如无法唯一定位课程时，不允许直接创建课次。

一个写入失败时，已成功的独立查询仍应返回。对于部分成功且需要补参的请求，待办只保留未完成部分，后续不会重复创建已经成功的课程或小测。

当前业务上限保持不变：一次一类管理动作，可组合创建一门课程及其一个课次；可额外生成一组小测，组合多个读取。超出上限的批量写入先说明限制，不由模型自行选择一项执行。

## 9. 写操作和幂等

写操作包括创建、修改、重试、更新知识点状态和生成小测。流程是：

```text
当前语义计划或有效待办明确授权
→ 目标唯一性检查
→ 参数和范围校验
→ 权限校验
→ 幂等键检查
→ 数据库事务
→ 保存 AgentAction 回执
→ 真实结果返回
```

写操作要求：

- 不从课堂文本或历史消息继承授权；
- 不猜测课程、课次、日期或标题；
- 同一消息重复执行不能产生重复数据；
- 已经完成或正在处理的任务不能重复提交；
- 成功、失败和部分成功都必须如实返回。

## 10. Agent 与 RAG 的关系

Agent 不直接实现向量检索，而是通过 `search_course` 或问答流程接入 RAG。

```text
Agent 判断用户要查询课堂内容
→ 调用 search_course 或课程问答
→ RAG 查询改写
→ BM25 + 向量召回
→ RRF 融合
→ Cross-Encoder 重排
→ 父块扩展
→ 返回证据
→ Agent 组织最终答案
```

RAG 返回的子块、父块、课次、时间和来源 ID 都属于工具证据。Agent 不能自己编造课堂结论或引用编号。

## 11. 最终响应格式和证据校验

Agent 最终使用结构化 JSON，常见结果类型包括：

```json
{
  "claims": [
    {"text": "课堂结论", "source_ids": ["E1"]}
  ]
}
```

需要澄清时：

```json
{
  "outcome": "needs_input",
  "question": "请提供课程名称",
  "claims": []
}
```

资料不足时：

```json
{
  "outcome": "insufficient_evidence",
  "claims": []
}
```

后端解析结果时校验：

- JSON 结构是否合法；
- claim 是否有文本；
- source ID 是否属于本次证据；
- 工具结果是否真实存在；
- 查询编号是否来自本次实际查询；
- 写操作是否有真实回执。

最终格式仍不合法时，只能从本轮真实证据恢复：全部要求的业务查询已完成且没有待执行写操作时，后端按已查询的编号重建结果，并重新核验权限和引用；不展示无效模型文本。名称查询确实为空且无法继续下游读取时，明确提示未找到匹配目标并请求确认，不声称整个查询完成。没有真实读取依据时仍返回校验错误。

## 12. 死循环和异常处理

### 12.1 死循环控制

通过轮数、调用次数、总时长和上下文大小控制工具循环。对于遗漏动作或查询，允许有限纠正；有效澄清和真实工具失败是停止催促写入的条件，不能为完成动作继续盲目重试。规划器格式修复和跨轮澄清另有独立上限。

### 12.2 工具异常

工具失败返回结构化错误。模型需要根据真实错误决定澄清、重试或结束，不能伪造成功。

### 12.3 大模型异常

模型超时、输出非法 JSON 或产生不允许的工具调用时，系统返回可控错误，并保留消息和执行状态，避免用户看到不确定的业务结果。

### 12.4 外部任务异常

转写、摘要和索引等异步任务通过状态记录进度。重试任务要求当前课次确实处于失败状态，已有文字时不会清空原内容，也不会把“已登记重试”说成“已经完成”。

## 13. 权限与安全

权限校验分布在多个层次：

```text
会话范围
→ 工具是否可见
→ 课程/课次归属
→ 工具参数校验
→ Service 数据查询
→ 最终引用和回执校验
```

课堂逐字稿、摘要和工具结果都视为不可信输入，不能执行其中的提示词或命令。用户消息中的明确授权优先于课堂文本，但仍不能越过后端权限。

写操作还需要防止：

- 模型添加未允许的字段；
- 用户通过自然语言修改他人课程；
- 重复提交任务；
- 利用历史消息伪造当前授权；
- 工具返回结果被模型篡改。

## 14. 可观测性和执行记录

当前已保存用户与会话范围、原始消息、请求状态、计划快照、待办状态、工具步骤、最终回答与引用。写操作由 `AgentAction` 保存真实回执，小测通过请求键关联实际小测实体。生成令牌用于防止已取消或被替换的请求继续写入。

工具步骤通过进度状态返回，便于定位哪些工具执行成功、哪些失败。当前新增请求级 JSON 追踪：从 `send_message` 进入到历史返回，用同一个业务 `request_id` 关联规划、模型、工具、检索、回答核验和保存过程；同一请求重试有独立 `trace_id`，子阶段通过 `span_id` / `parent_span_id` 组成调用树。SSE 首个状态事件包含业务 `request_id`；后台工作线程自己建立追踪上下文，并发请求之间不共享状态。

追踪记录阶段耗时、数据库调用数与耗时、模型提供方及型号、供应商实际报告的 token、工具错误码、格式修复和降级原因。意图规划与执行提示词记录内容摘要作为 `prompt_revision`，便于对照版本定位行为变化。只记录不可逆摘要，不写入提示词正文。

请求结束会输出一条 `request.finished` 汇总，包括业务结果、模型/工具调用与错误数、修复/降级数、SQL 数量和 token 小计。供应商缺报或部分报告用量时保留缺报及分字段报告调用数，不把缺报估算成真实用量，也不据此计算货币费用。数据库指标只覆盖实际 SQL 执行，不包含连接池等待、事务提交耗时和完整 ORM 处理时间；父子阶段耗时含嵌套部分，不能相加为请求总耗时。

日志使用独立的 `classagent.trace` logger，输出一行一个 JSON，可由容器日志系统收集。原始提问、回答、课程名称、工具参数/结果、SQL/参数、模型思考、密钥和异常详情均不写入追踪日志。用户和资料范围只记录后端标识。异常仅保留类型、状态码或固定原因码，日志输出故障不改变业务执行或重试行为。

脱敏追踪现在通过独立事务持久化到数据库，管理员可从左侧「运行监控」查看概览、筛选分页和执行详情；聊天消息中的执行详情入口只返回当前用户自己的追踪。管理员权限以数据库角色为准，普通用户不能调用管理接口。运行中的请求仅展示开始摘要，阶段在结束时保存；异常丢失的结束记录单独标记，不能视为成功。阶段及原因码、指标口径和权限说明见 `docs/agent-observability.md`。尚未接入集中式追踪服务、自动告警、HTTP 鉴权前的追踪或 Celery 跨进程链路传播。

## 15. 测试和质量评估

Agent 测试分为：

### 15.1 意图和工具选择

- 查询是否选择正确工具；
- 多意图是否调用多个工具；
- 缺少参数是否澄清；
- 明确否定是否不执行写操作。
- 待办能否保留题量、题型、日期等参数；
- 取消、换话题、过期后能否阻止旧任务恢复；
- 非法计划是否仅修复一次并关闭写权限。

### 15.2 工具和权限

- 参数非法是否被拒绝；
- 他人课程是否不可见；
- 当前课程范围是否不能越界；
- 重复消息是否幂等；
- 工具失败是否如实返回。

### 15.3 RAG 和答案

- 课次 Recall；
- 子块 Recall@K；
- 父块证据覆盖率；
- 引用准确率；
- 答案要点覆盖率；
- 资料不足时是否拒答。

### 15.4 系统指标

- 首字节和完整响应延迟；
- 工具调用次数；
- 循环终止率；
- 模型和工具错误率；
- 降级率；
- token 和单次请求成本。

### 15.5 本次验证方式

确定性回归覆盖类型契约、待办生命周期、权限、幂等、参数篡改、并发取消和数据库迁移。既有工具测试在规划边界使用固定计划夹具，避免业务执行测试依赖网络；新增语义测试单独验证模型输出处理，不能把工具测试全部解释成真实模型理解率。

另以真实模型调用 `send_message`，使用隔离的 SQLite 数据和真实业务处理器，核对回答、实际工具、数据库变更及引用。测试集包含原有 33 个场景与新增 20 个场景，覆盖自然表达、多步操作、否定/引用、取消、换话题和多轮参数纠正。最新完整结果与失败修复记录以本地 `test-results/full-validation-20261101/report.md` 为准。

2026-11-01 完整验证结果：后端全量 381 项通过，另有 12 个通过子测试；前端单元测试 7/7，生产构建通过；修复后的真实模型场景为 33/33、20/20，独立 PostgreSQL/Redis/Celery/API 联调 12/12，实际浏览器端到端 6/6。最终代码的各层均重新验证；各层不能相加解释成模型理解率，执行日志见完整报告。

联调覆盖旧库兼容迁移、跨用户隔离、SSE、并发幂等、规划中取消、实际音频上传/ASR/纪要/索引、混合搜索、出题和转写重试。音频使用中文合成语音；数据库、账号和上传存储均独立于用户原有数据。浏览器验证登录、组合操作卡、历史保存、工具过程和引用时间点跳转。

## 16. 当前实现与企业级演进

已实现：

- 每轮语义规划、强类型计划校验和模型驱动的工具选择；
- 持久化待办、请求计划快照和有界澄清续接；
- 工具注册、Schema 和后端执行器；
- 多工具循环；
- 参数、权限和业务校验；
- 写操作幂等和真实回执；
- RAG 混合召回和证据引用；
- 死循环限制和外部服务降级。

后续可以演进：

1. 依据真实评测优化规划延迟与成本，必要时引入轻量模型或版本化缓存；
2. 当前待办是会话级有限状态；长时间任务、复杂依赖图、审批和补偿事务仍需工作流引擎；
3. 在现有请求级 Trace 基础上接入集中采集、告警，并扩展 HTTP 鉴权和 Celery 跨进程链路；
4. 增加 Prompt、工具 Schema 和模型版本管理；
5. 增加线上用户反馈和 Agent 成功率评测；
6. 增加限流、缓存、熔断和多模型路由。

新增业务工具时，应同步扩展意图 Schema、必填参数检查、意图到工具/回执映射、授权处理器、工具注册和测试集。先确定业务上限、事务边界和恢复策略，再开放批量操作；不通过增加关键词或放宽工具权限代替这些约束。

## 17. 技术路线总结

ClassAgent 当前采用“模型理解、工具执行、后端裁决”的 Agent 架构：

```text
自然语言输入
→ 用户与范围校验
→ 语义计划与类型校验
→ 待办状态与本轮授权
→ 大模型选择工具
→ 后端验证并执行
→ 工具结果回传
→ 受限循环编排
→ 证据/回执校验
→ 最终答案或操作结果
```

这种设计让大模型负责处理自然语言和任务编排，让后端负责权限、数据一致性和业务真实性，适合继续扩展课程管理、学习记录、RAG 问答和练习生成能力。
