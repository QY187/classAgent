# Agent 记忆机制

更新时间：2026-11-25。已合入 main 并随当日版本部署；记忆开关保存时只提交两个可写字段的修复也已上线并推送。本次生产仅做启动/健康检查，未进行业务验收；下列模型与界面验证是此前开发阶段记录，见 [部署记录](production-deployment.md)。

## 当前调用前压缩机制（2026-11-24改造）

默认记忆预算已按用户要求调整为16000估算Token，触发比例仍为80%，即约12800；实际触发点会扣除当前问题和协议预留。环境变量MEMORY_CONTEXT_BUDGET仍可覆盖默认值。

主流框架的共同设计是“调用前检测压力→达到阈值先压缩→检查点+近期原文继续”，后台预热不代替调用前保障。参考：

- LangChain SummarizationMiddleware：https://reference.langchain.com/python/langchain/agents/middleware/summarization/SummarizationMiddleware
- Claude Context editing：https://platform.claude.com/docs/en/build-with-claude/context-editing

ClassAgent现于当前问题落盘并发布开始事件后、意图规划和工具执行前，计算未压缩尾部+检查点的用量。当前问题与协议余量从应用会话预算中预留；达到可用预算80%时，同步滚动压缩旧前缀，再调用问答模型。当前默认16000是应用分配给对话记忆的估算预算，不是供应商整个上下文窗口，也不是精确分词结果。

压缩合并旧检查点及新消息，保留有来源的关键摘录（用户约束、纠正、主题和未解决问题），用through_position/version记录覆盖点。通常保留最新两轮原文，长轮次可减少保留数以避免完全丢掉；单批按完整问答切分，上限约12000估算Token。读取已覆盖前缀不再重复注入近期历史，旧内容可在需要时另行检索。检索提示只传承接所需字段，完整UUID出处保留在后端与界面。预热及压缩均复核原文，空摘要不能标记为已覆盖。

同步压缩最多三批，45秒预算，每次请求配置最多20秒超时，成功后再次核对是否低于硬预算。并发后台任务通过版本CAS协调，用户停止生成后不再保存该压缩结果。压缩期间不持有会话行锁，界面显示“压缩较早对话，保留近期上下文”。失败或积压过多导致本次仍超预算时，明确暂停本轮并保留原聊天供重试，不静默裁掉未压缩前缀回答；额度不足仍显示真实额度原因。关闭历史或临时模式按用户选择不压缩，只保留预算内近期交流。仅关闭后台生成配置但历史仍开启时，超预算也暂停，不静默丢弃。

此机制是带出处的抽取式滚动压缩，并不保证保留所有逐字细节；课堂事实和业务操作仍须重新核实。原文始终保留。后台Celery摘要继续作为提前准备，未完成时由调用前压缩补齐，不靠后台速度保证连续性。老对话不再受此前最近200条候选限制影响其压缩覆盖，按检查点后的前缀分批推进。

验证（使用当时6000预算）：一次性合成16轮对话，真实默认模型一次memory_compaction调用，将估算上下文10762压至2306，最早Python约束仍在、近期4条消息完整保留，检查点覆盖至位置27。临时账号、聊天及额度记录已清理，未读取真实用户历史。100项相关回归通过，1项此前确认的基线引用断言排除；另有29项长对话/对抗测试、34项压缩及流式/失败分类测试通过；覆盖压缩先于规划、滚动保留约束、超过200条旧历史逐批续接、停止生成不写检查点。旧对抗测试中的固定8条窗口断言已按新契约更新为预算与完整轮次、无孤立澄清及不产生越权动作。

以下三阶段说明保留数据层、长期记忆及管理功能；有关同步时机、预算分配和失败策略以上述当前机制为准。

## 第一阶段：近期上下文与来源摘要

历史按完整已完成问答轮次选取，默认约16000 Token估算预算。中文每字按2、其他连续文本每3个UTF-8字节按1估算并加入协议余量，属于模型无关近似，不是供应商实际Token计量；实际额度仍由供应商用量结算。目前不按模型动态扩容。近期问答优先，通常预留三分之一给其他记忆；最新完整轮次需要时可借用整个预算，不截断单条消息。当前读取检查点之后的完整问答轮次，压缩及上下文构建不再以最近200条为截断边界；近期原文最终仍按预算选择。当前问题和协议余量另行从可用预算预留。

较早消息累计超过3000预算单位，保留最新四轮后，Celery异步更新抽取式摘要。摘要模型只选择原消息连续摘录，保存source_id、through_position和version；读取时重新核对来源与原文，版本CAS阻止旧任务覆盖。原始消息不压缩、不删除，已删除来源不能召回。摘要是话题线索，不是课堂事实或操作授权。后台失败不影响回答，后续消息可重新触发。

模型调用复用当前服务端默认模型和用户额度，purpose=memory_summary单独记账；MEMORY_SUMMARY_ENABLED=false可停止摘要生成。第一版敏感词命中时整条排除摘要、在近期上下文中用占位替换，不改原始聊天记录。不能承诺识别没有任何标签的所有秘密。

验证：4项记忆专项通过；聊天、Agent、范围、失败说明相关回归46通过，1项既有引用测试失败。在未修改基线b3ace7a独立归档中复现同样失败：不完整模拟引用现应标为unavailable，旧测试仍只期望id。未改变这部分业务逻辑。

## 第二阶段：历史混合召回

查询阶段先按本人及课程/课次范围做SQL过滤，回收站内容沿用统一可见性规则。关键词检索原始消息，支持已有历史无需回填；向量索引只保存消息ID、内容哈希、模型和1536维向量，不复制完整原文。近期完成消息由Celery增量建立索引，每批最多12条；索引HTTP请求超时配置4秒、问答检索3秒，失败保留关键词结果。向量召回仅在PostgreSQL、配置有效向量服务且维度1536时启用。无有效配置时为关键词召回，不宣称已做语义检索。尚未提供批量历史向量回填。

MEMORY_SEMANTIC_ENABLED控制问答向量检索；embedding调用以memory_embedding计入用户额度。结果返回原会话、消息ID、时间及原文摘录，进入Agent参考数据，旧回答不能代替课堂依据。历史、摘要与长期偏好共用总预算约16000估算Token，其中历史召回最多1600。敏感消息不入向量、不被召回；索引读取核对原文哈希。

验证：新增用户隔离、课程/课次隔离、回收站、删除来源、敏感内容、无匹配测试，与第一阶段合计7项通过。

## 第三阶段：明确记忆与可管理界面

新增user_memories、user_memory_settings、conversation_memory_policies、chat_memory_uses。记忆由用户通过管理页面或固定聊天格式明确保存，不自动从普通聊天抽取用户画像。字段包括本人、可选课程、来源消息、版本和时间；最多100条、单条2到300字。编辑采用版本比较防止覆盖；凭据标签命中时拒绝保存。课程/课次对话读取全局及本课程偏好，主对话仅使用全局偏好，避免不同课程偏好互相干扰。

接口：GET/POST /memories，PATCH/DELETE /memories/{id}；GET/PATCH /memory-settings；GET/PATCH /chat/conversations/{id}/memory-policy；GET /memory-sources/{id}。所有接口后端绑定本人并校验课程、会话归属和可见性。来源消息删除后，依赖该来源的记忆和使用记录级联删除。删除聊天保留其他来源或手动创建的记忆。管理页面手动编辑后视为新的明确保存，解除旧聊天来源依赖；同内容再次保存更新为最新来源。历史记忆命令与其回执不参与摘要、近期普通上下文、关键词或向量召回，避免已删除偏好由旧“已记住”回执复活。

页面 /memories 支持添加、编辑、删除、来源查看及两项开关，入口在个人设置与问答“记忆”菜单。临时模式停止摘要、跨会话召回和长期记忆读写；仍保存聊天，保留当前对话近期问答。关闭历史会清除派生摘要和向量，保留原聊天；关闭长期记忆保留已有条目供管理。恢复开关后原聊天可再次参与关键词检索。用户仍须自行删除不想保留的原聊天。

聊天支持精确格式“记住：内容”“全局记住：内容”“忘记：完整内容”“修改记忆：原内容 => 新内容”；在同一数据库事务保存命令、回执与记忆，不调用模型，不恢复其他业务写授权，重复request_id仅回放。普通自然语言记忆操作暂通过产品说明引导，不伪造保存成功。用户偏好也交给最终综合回答，仅影响与当前问题、事实及协议不冲突的表达方式。

回答可展开“本次提供的记忆参考”，展示实际交给Agent的历史摘录和偏好，附来源入口；不宣称模型确实采用了每条参考。读取时核对当前权限、来源原文及记忆版本，变化时标记或停止展示。记忆读取和出处记录采用保存点隔离，故障降级到近期问答，不撤销业务回答。

## 当前限制

预算是模型无关的近似分词而非精确Token上界；摘要是模型挑选的可核对摘录，不是自由改写的抽象总结。关键词候选最多80条，向量近邻最多12条，返回最多4条；不承诺任意历史都能命中。无批量历史向量回填，旧历史先走关键词，近期消息增量索引。摘要失败由后续消息重试，无独立状态管理页或定时补偿。没有自动画像、知识图谱、自动判定掌握程度或改写业务事实。

最终历史预算默认约16000估算Token，可用MEMORY_CONTEXT_BUDGET调整到512至24000。按近期完整轮次、摘要（最多800）、当前适用偏好（最多1000）、相关历史（最多1600）顺序使用剩余预算，总额受同一预算限制。MEMORY_SUMMARY_ENABLED和MEMORY_SEMANTIC_ENABLED可通过Compose环境控制；禁用语义同时停止索引。摘要与向量调用分别以memory_summary、memory_embedding计入用户额度，均有超时；请求追踪记录memory.context、memory.recall和memory.embedding阶段耗时及召回数量，不记录原文。向量服务缺失或配置维度非1536时只用关键词。
