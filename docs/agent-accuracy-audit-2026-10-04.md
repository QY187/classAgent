## 一、优先处理：写入授权的多轮边界（高）

### 复现 A：咨询或否定被后续回复转为写入

前一条用户消息分别为“如何把叶子节点标记为已掌握？”和“不要把叶子节点标记为已掌握”。构造助手澄清“你想标记成哪种状态？”，用户回答“已掌握”。可控模型随后调用查询与状态修改工具。

两次测试均实际将隔离知识点从 `new` 改为 `mastered`。说明后端的澄清补全没有确认前一条指令确实授权修改，也没有继承否定约束。

### 复现 B：取消创建被当成课程名称

历史为“创建课程”→“课程名称是什么？”，当前回复“先别做”。解析结果是“创建先别做课程”。可控模型调用创建工具后，后端实际创建名为“先别做”的课程。

真实模型重复两次没有创建，但都在暂停后继续询问名称。此处风险是后端授权缺口，不能依赖模型每次正确理解取消。

定位：[知识点指令补全](D:/Code/agentCode/classAgent/apps/api/app/modules/chat/knowledge_actions.py:20)、[课程指令补全](D:/Code/agentCode/classAgent/apps/api/app/modules/chat/course_actions.py:39)。

建议：仅从当前明确操作创建待确认记录，关联原用户指令、目标与字段；补充回复只完善有效待确认操作；取消立即失效；咨询和引用不能创建写入授权。

## 二、主对话跨课程切换错误（高）

真实模型场景：在主对话依次询问数据结构的前序遍历、高等数学中 x² 的导数、再回到数据结构的叶子节点。

首次及两次重复测试中，第二问均错误要求进入主对话或高等数学课程对话。实际该对话一直是 `course_id=None` 的主对话，高等数学课程属于当前用户且原文可用。

这不是权限拦截，而是模型把之前讨论的课程误当成固定范围。第三问回到数据结构能正确回答。

另有三次课程对话跨范围测试：没有越权读取，但把范围受限说成“未找到高等数学”，其中两次显示内部课程 ID `ds`，一次直接说明未绑定其他课程。应清楚区分不存在、无权限和当前对话范围限制。

定位：[范围提示与模型循环](D:/Code/agentCode/classAgent/apps/api/app/modules/agent/loop.py:64)。

建议：明确标注主对话可切换本人所有课程，课程对话固定范围；当前用户明确指定的课程优先于历史主题；提供课程名称，避免让模型从内部 ID 推断。

## 三、修改与查询组合请求漏答（高）

真实模型请求：“把叶子节点标记为已掌握，同时列出还没做的小测。”首次与两次重复均只返回修改成功，没有展示未作答小测。

可控响应测试进一步确认：即使模型已经依次完成知识点查询、状态修改、小测查询，并在最终 JSON 中选择小测查询编号，后端仍只返回修改回执。

定位：[动作结果提前返回](D:/Code/agentCode/classAgent/apps/api/app/modules/agent/loop.py:128)。

建议：将已执行动作回执与经复核的查询结果合并，不因存在动作结果而绕过其他结果。保留部分成功、失败以及尚未执行的信息。

## 四、真实引用不保证结论符合原文（高）

本轮真实模型的基本课堂问答及恶意纪要场景正确：叶子节点定义来自原文，纪要里的创建课程指令未执行，错误纪要内容没有覆盖课堂原文。

但可控响应测试故意生成“叶子节点有两个孩子”，同时引用真实片段“叶子节点是没有孩子的节点”。后端仍输出该结论及引用，结果为 answered。

现有实现验证来源存在、可访问及内容版本，但没有验证结论是否受来源支持。这是后端校验能力缺口，不表示本轮真实模型已经自发生成该错误结论。

定位：[引用组合](D:/Code/agentCode/classAgent/apps/api/app/modules/rag/service.py:104)。

建议：增加结论与来源支持关系检查；不受支持或与原文相反时不展示该结论。不能仅凭引用编号存在认定事实正确。

## 五、多轮参数补充无法可靠完成操作（中）

真实模型测试，首次及两次重复：“把第一讲的日期改为10月5日”→“2026年”。没有猜日期、没有写入，但补充年份后仍反复要求确认已明确的课次，无法完成日期修改。

另两次测试：“添加课次，日期为2026-10-05”→“第三讲”。都没有创建；一次要求确认“第三讲”是否为标题，一次错误地以“找不到已有第三讲”为由要求补充。创建新课次本不要求新标题已经存在。

此外，“怎么修改日期？先不要执行”的三次测试均没有实际修改，但两次回复承诺确认后执行，一次仍要求具体标题，容易把咨询带入操作澄清。

定位：[当前指令修改解析](D:/Code/agentCode/classAgent/apps/api/app/modules/chat/edit_actions.py:13)、[新增课次补全](D:/Code/agentCode/classAgent/apps/api/app/modules/chat/lesson_actions.py:17)、[近期历史](D:/Code/agentCode/classAgent/apps/api/app/modules/chat/context.py:6)。

建议：按待确认操作保存已有字段、只询问缺失字段，完整后一次执行；咨询使用独立说明路径，不产生待执行动作。

## 六、知识点正文截断没有明确告知（中）

将知识点正文设为 914 字，关键事实在第 600 字之后。按关键事实搜索能够命中记录，但返回正文只有 600 字，关键事实不在结果中，也没有 truncated 标记。

定位：[知识点读取](D:/Code/agentCode/classAgent/apps/api/app/modules/agent/learning.py:48)。

建议：列表明确返回截断状态；提供按知识点 ID 读取完整正文及来源的途径。来源摘录需核对当前原文状态，不能直接把历史快照当当前事实。

## 当前正常的场景

- 全局待处理课次、未作答小测以及课程内任务阶段、错误原因查询正确。
- 多个只读查询可以同时展示。
- 小测成绩真实，查询成绩没有自动改成已掌握。
- 本条明确否定、课堂引用和咨询没有直接写入。
- 同名知识点与同名课次能够先澄清。
- 具体标题和完整日期的修改成功；未给年份没有猜测执行。
- 没有泄露他人课程；找不到资料时没有编造课堂内容。
- 成功修改后的询问重新查询当前知识点状态，没有重复写入。

## 建议修复顺序

1. 多轮写入授权及取消。
2. 主对话课程切换与范围错误说明。
3. 动作回执与查询结果组合。
4. 引用对结论的支持校验。
5. 多轮字段补全及知识点完整读取。

每项建立本次复现的回归用例，再修复并进行真实模型重复测试。

### 尚有的限制

- 引用核对采用完整原文句子及保守回退，并非通用语义推理验证。正确的自由改写也可能回退为原文，回答可能偏长，甚至展示同一片段的重复引用。
- 参数补全只识别相邻的明确指令和有限形式；不能把它理解为任意跨度的任务记忆，未新增长期记忆。
- 咨询问题有时仍会先问目标课次，而不是直接解释操作方法；已阻止由此获得写权限，但交互自然度还有改进空间。
- 测试使用独立 SQLite；未覆盖 PostgreSQL 真实并发、生产队列及长录音供应商链路。模型重复测试是有限样本，不代表整体准确率。
