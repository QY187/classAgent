# Agent 最终响应与协议修复

主对话和整门课程对话的工具循环使用统一的最终响应结构。`responses.py` 负责校验课堂结论、目录、业务查询编号和澄清问题的类型；来源权限、版本及业务统计仍由对应结果存储重新核验。

- 历史中的助手消息是面向用户的渲染结果，不作为本次响应格式示例。简短追问可承接最近用户明确讨论的目标，但必须重新读取依据，不能沿用历史引用。
- 澄清使用 `needs_input` 和最多 300 字的 `question`，不能混入课堂结论或业务查询结果。没有资料时使用 `insufficient_evidence`。
- 模型额外填写的自由答案、分数等字段不会进入展示；成绩、数量和执行结果仍来自真实业务数据。
- 最终响应结构或查询编号校验失败时，最多增加一次修复机会。模型可以继续读取必要资料，再返回合法结果；不能直接放行普通文字回答。
- 修复最多额外占用一轮，工具调用总数和 90 秒执行预算不变。每轮仍检查取消与范围权限，第二次最终响应错误正常返回失败。
- 已成功的写动作仍由真实回执呈现，不因格式修复重复执行；此项不改变写操作授权规则。

## 课堂内容位置

用户只问某个主题在哪门课程、哪节课或哪个时间点时，语义规划标记`answer_mode=source_location`，不把内部定位用的知识点查询计为用户要求展示的学习清单。执行模型可以查询知识点、目录、纪要寻找候选，再通过`search_course`或`get_transcript`读取匹配主题的当前原文。

最终返回`{"claims":[],"locations":{"source_ids":["E1"]}}`。后端核对本次证据、用户权限、原文版本及课次归属，用数据库中的当前课程名称和课次标题生成简短回答，按课次去重，保留可跳转到时间点的引用。不接受模型自由填写课程名称或“第几讲”，不把位置元数据送入课堂原文逐句校验。

仅定位模式下，即使模型附带目录、学习状态或课堂解释，也只呈现核验过的位置；未提供位置时进入既有的一次协议修复。找不到有效来源时保留不足说明或必要澄清，不凭标题猜测。查询状态清单、解释课堂知识等混合请求仍用标准模式，可组合`locations`、`learning`和`claims`。

旧消息及其请求快照不自动改写；重新发送问题走新规划，原请求重放仍遵循既有幂等语义。

## 验证

新增回归覆盖普通文字澄清修复、修复后读取原文、伪造引用拒绝、错误字段类型、澄清与事实混用、修复期间取消、最后一轮修复和单次修复限制。既有学习记录/成绩测试继续确认模型附加的答案及分数不会覆盖业务记录。

隔离数据的真实模型复测中，主对话连续追问、课程切换并切回、课程内前序/中序比较以及缺少课次标题的澄清正常返回。普通小测生成和同请求重试仍只产生一组题，卡片不含答案解析。真实模型结果是本次样本验证，不代表所有自然语言表述都能一次成功。

## 目标交付与精确原文引用（2026-11-02）

语义规划增加goal、outputs和requirements，保留用户要求的结果类别、状态、主题和定位课程范围。内部辅助查询不自动展示，最终选中的查询须满足条件；缺纪要查询使用课程进度中的缺纪要视图。类别或条件不符合时在原有预算内修复一次，未完成部分如实说明。

父块按实际可见的原始逐字稿片段分别建立证据，核对课次归属、权限和版本；截断外或他人来源不认证。同源读取复用引用、重复句子去重，错误引用不再回退为无关标题。

请求级执行状态按Schema归一化参数，连续两次同参数读取结果未变时阻止第三次重复调用，反馈无匹配、分页、失败及无进展。写入成功后清空观察，不改变授权与幂等规则。
