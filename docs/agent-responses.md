# Agent 最终响应与协议修复

主对话和整门课程对话的工具循环使用统一的最终响应结构。`responses.py` 负责校验课堂结论、目录、业务查询编号和澄清问题的类型；来源权限、版本及业务统计仍由对应结果存储重新核验。

## AI 综合回答（当前展示链路）

新计划的读取问答采用“工具检索与业务查询 → 后端核验并形成事实材料 → 大模型综合解释 → 引用及语义一致性检查 → 再核对资料版本 → 展示与保存”。`claims`中的完整原句和业务结果是内部事实材料，不再作为常规成功回答直接展示。

`synthesis.py`只接收当前问题和已经筛选、核验的材料，不接收未选中的候选清单。综合模型用自己的话归纳、对比、解释概念和组织结果；简单问题可一句话回答，复杂问题按需要分段，不强制按工具类别套标题。比如解释“最多两个孩子”可以说明它限制的是上限，并不意味着每个节点恰好有两个孩子。事实可自然改写，不能新增无依据的案例、状态、数量或操作成功。

模型返回带`material_ids`与`citation_ids`的段落。后端检查材料覆盖、引用范围和类型；另一轮模型调用检查文本是否忠于材料、是否完整回应问题，重点核对否定、条件、数字、课程范围和学习状态。该阶段允许概括，**不做逐字相等要求**。模型语义检查是质量约束，不是数学证明，也不能替代权限或数据库真实性校验。

常规综合包含一次生成和一次一致性检查；结构、引用或语义检查未通过时最多修复一次，整个阶段共用35秒预算。超额、模型服务失败及取消继续走已有错误和取消链路，不隐式重试付费调用，也不悄悄把失败的综合回答换成原始检索清单。

展示前重新生成同一组已核验材料；原文、名称、权限或学习记录在综合期间变化时停止保存旧答案，提示重新查询。引用编号、原文片段和跳转时间由后端决定，同一来源去重。内部材料不进入聊天预览或消息接口，保存的是模型组织后的正文与公开引用；同请求成功重放不再次调用模型。

纯操作成功回执、澄清、失败和证据不足提示保留原业务处理；混合写入的回执也不经自由改写。本次没有放宽任何写权限。旧计划快照没有`outputs`时保持兼容，旧历史消息不自动重写。

- 历史中的助手消息是面向用户的渲染结果，不作为本次响应格式示例。简短追问可承接最近用户明确讨论的目标，但必须重新读取依据，不能沿用历史引用。
- 澄清使用 `needs_input` 和最多 300 字的 `question`，不能混入课堂结论或业务查询结果。没有资料时使用 `insufficient_evidence`。
- 模型额外填写的自由答案、分数等字段不会进入展示；成绩、数量和执行结果仍来自真实业务数据。
- 最终响应结构或查询编号校验失败时，最多增加一次修复机会。模型可以继续读取必要资料，再返回合法结果；不能直接放行普通文字回答。
- 修复最多额外占用一轮，工具调用总数和 90 秒执行预算不变。每轮仍检查取消与范围权限，第二次最终响应错误正常返回失败。
- 已成功的写动作仍由真实回执呈现，不因格式修复重复执行；此项不改变写操作授权规则。

## 课堂内容位置

用户只问某个主题在哪门课程、哪节课或哪个时间点时，语义规划标记`answer_mode=source_location`，不把内部定位用的知识点查询计为用户要求展示的学习清单。执行模型可以查询知识点、目录、纪要寻找候选，再通过`search_course`或`get_transcript`读取匹配主题的当前原文。

最终返回`{"claims":[],"locations":{"source_ids":["E1"]}}`。后端核对本次证据、用户权限、原文版本及课次归属，用数据库中的当前课程名称和课次标题生成简短回答，按课次去重，保留可跳转到时间点的引用。不接受模型自由填写课程名称或“第几讲”，不把位置元数据送入课堂原文逐句校验。

仅定位模式下，即使模型附带目录、学习状态或课堂解释，也只呈现核验过的位置；未提供位置时进入既有的一次协议修复。找不到有效来源时保留不足说明或必要澄清，不凭标题猜测。查询状态清单、解释课堂知识等混合请求仍用标准模式，可组合`locations`、`learning`和`claims`。

旧消息及其请求快照不自动改写；重新发送问题走新规划，原请求重放仍遵循既有幂等语义。

## 按交付目标组织回答

语义规划现在同时返回`goal`（一句话描述用户要获得的结果）和`outputs`（需要展示的结果类别）。例如“在哪讲过并解释特点”对应`["locations","claims"]`，需要复习的清单对应`["learning"]`，纯写操作的`outputs`为空，结果使用真实操作回执。业务类别必须与既有`queries`一致，契约本身不授予写权限。

后端把它们作为`response_contract`传给执行循环，并与请求计划一起持久化。输出类别使用既有回答结构，覆盖课堂内容、内容位置、目录、学习记录、课程进度、成绩和处理记录；不是新增一组按问法匹配的正则。旧快照可不包含该契约，继续遵循原流程。

工具查询是执行过程，不自动成为展示内容。组合回答只呈现契约要求的类别。最终JSON即使结构合法，缺少用户要求的类别时也触发既有的一次修复，让模型继续读取或补齐回答；成功写入不得重做。修复后仍缺失时保留已核验的部分并说明未完成项。实际渲染也检查引用及业务结果，失效引用不能仅凭字段存在算完成。必要澄清仍可正常结束，不为了补齐字段编造事实。

该机制检查类别覆盖和证据有效性，不能证明每句话都语义完整或确实回应了主题；例如同一类别下要求多个知识点时，仍依赖模型理解、检索质量和样例评测，不应将结构核验等同于独立语义裁判。

### 查询条件与面向用户的结果

`requirements`补充结果类别之外的筛选语义：学习记录的视图、状态、主题关键词，以及是否限定到本轮原文定位的课程；进度可指定`missing_summaries`，只展示没有可用纪要的课次。它由同一次语义规划提取，不增加按问法匹配的正则，也不改变写授权。旧快照默认空条件，保留兼容。

例如“解释二叉树的两条性质，查看相关知识点中需要复习的内容，以及这门课缺少纪要的课次”，规划为`locations + claims + learning + progress`；学习条件为`knowledge_points / review / 二叉树 / located_courses`，进度视图为`missing_summaries / located_courses`。不是查询所有状态后把全部条目直接展示，也不能用一般待处理课次代替缺纪要查询。

执行循环核对最终选中的查询编号：工具类型、状态、主题关键词必须符合条件，课程必须属于本轮有效位置引用定位到的课程。辅助查询编号不能代替符合条件的结果。缺少条件或引用错误时使用原有的一次修复机会；修复耗尽仍不符合的部分不展示，并说明尚未完成，不回退输出宽范围候选清单。

后端按内容出处、课堂说明、学习记录、纪要等结果准备事实材料。学习材料保留符合条件的条目、真实空结果及分页提示，省略用户没要求的全状态统计；只问缺纪要时省略总体进度和知识点数量。最终自然语言由综合模型按问题组织，不直接显示这组内部分类。业务数据仍在展示前重查。


### 父块与原文片段的对应

检索父块的`source_segment_ids`可能包含多个原始逐字稿片段，不能让整块内容共用首段的引用编号。证据收集逐段检查课次归属、权限及本轮实际可见文字，在工具结果的`evidence`数组中返回各段文字、编号和时间点；截断范围之外的文字不会因为出现在来源ID列表中就自动获得引用资格。相同读取复用证据编号，重复句子只展示一次。

原文再次核对权限、版本和范围。内部事实选择中的课堂句子必须对应本轮已读完整原句，错误引用进入修复，不再用首段标题自动替代解释。旧无契约链路保留保守的原文回退兼容。当前采用“抽取核验事实 + 生成式综合回答”的分层方式，最终正文可以自然改写，由引用检查、模型语义检查和资料重查共同约束；真实性与回答质量仍需要分别评测。

## 根据执行结果调整下一步

请求内的`ExecutionState`按工具Schema归一化参数，比较实际返回结果。相同参数连续两次结果未变时，第三次相同读取返回`no_progress`，避免继续查询数据库或外部服务。改变关键词、来源或分页可继续，成功写入清空读取观察，允许重新核对最新状态。它不缓存工具数据或授权，不拦截原有写操作幂等机制。

工具结果附加固定的运行反馈，区分无匹配、需要分页、读取失败和重复无进展。反馈不拼接课堂原文或异常详情。模型据此决定换查询方式、继续分页、呈现已核验部分或必要澄清；不会自动越权、扩大写入范围或循环重试。原有6轮、8次调用、90秒及一次修复预算继续生效；被阻止的重复请求仍消耗调用预算并在聊天步骤显示失败。

## 验证

新增回归覆盖普通文字澄清修复、修复后读取原文、伪造引用拒绝、错误字段类型、澄清与事实混用、修复期间取消、最后一轮修复和单次修复限制。既有学习记录/成绩测试继续确认模型附加的答案及分数不会覆盖业务记录。

隔离数据的真实模型复测中，主对话连续追问、课程切换并切回、课程内前序/中序比较以及缺少课次标题的澄清正常返回。普通小测生成和同请求重试仍只产生一组题，卡片不含答案解析。真实模型结果是本次样本验证，不代表所有自然语言表述都能一次成功。
