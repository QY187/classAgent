# 主对话与课程对话工具执行进度

## 后端

主对话复用 Agent 的 `on_step` 回调，通过已有提问 SSE 新增 `step` 事件：`{request_id, steps}`。每次发送当前请求的完整步骤快照，前端可按请求编号替换，不依赖增量拼接。步骤包含 `id`、固定中文 `label`、`status`（running/completed/failed）及安全失败说明，不返回模型参数、原始工具结果或内部异常。

步骤保存到提问消息的 `agent_steps_json`，普通历史接口增加 `steps`；历史消息默认空数组，已有数据库通过幂等迁移补齐字段。新请求独立保存，重试清空旧步骤，幂等重连不重复执行。每次写入重新校验用户归属、生成令牌及 pending 状态；停止或失去生成占用后不再写入、发送工具步骤。失败和停止时保留已发生的记录，前端根据消息终态标明未完成步骤已中断。

主对话和整门课程对话使用 Agent，并保存真实工具步骤；旧课次对话沿用原 RAG，不伪造工具步骤。步骤不会改变来源校验、模型预算、回答保存与取消规则。目录名称与工具读取内容仍在原回答中展示，进度面板不额外复制资料。

## 验证

27 项相关测试通过，覆盖 SSE 顺序、历史读取、工具失败后继续、失败重试清空旧步骤、请求幂等以及停止后禁止发布。PostgreSQL 字段迁移重复执行通过。

## 页面展示

步骤在对应问题之后、助手回答之前展示。进行中默认展开，完成后默认折叠为步骤数量，可手动展开详情；工具错误显示在具体步骤下。失败或停止时，未结束的工具标为已中断，不继续显示进行中。重试与后续提问按 request_id 隔离，旧请求事件不能更新当前问题。

刷新或切换回来使用普通历史接口恢复；原有两秒轮询也会恢复正在执行的步骤。当前未提供后台任务恢复或工具重新执行按钮。

页面接入后，58 项相关后端测试、前端类型检查和生产构建通过。本地真实模型验证原文问答与后续目录查询分别保存三个执行步骤，默认折叠、手动展开及刷新恢复均通过；验证对话已清理。
