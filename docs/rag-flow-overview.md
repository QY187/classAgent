# ClassAgent RAG 流程说明

## 1. RAG 解决什么问题

ClassAgent 的 RAG 用于让用户基于课程逐字稿提问，并返回带课次和时间定位的答案。系统只使用当前用户有权限访问的课程内容，检索不到足够证据时返回资料不足，不让模型凭空回答。

整体流程是：

```text
音视频
→ ASR 逐字稿
→ 父子块切分
→ 向量和 BM25 索引
→ 用户提问
→ 查询改写
→ 混合召回
→ RRF 融合
→ Cross-Encoder 重排
→ 父块上下文扩展
→ 大模型生成答案
→ 引用校验和返回
```

## 2. 数据处理和索引

用户上传音视频后，系统异步完成转写。ASR 结果保存为 `TranscriptSegment`，每个片段包含：

- 说话人；
- 开始和结束时间；
- 原始文本；
- 原始片段 ID。

随后系统对逐字稿建立 RAG 索引：

```text
TranscriptSegment
→ 父块和子块
→ 生成 embedding
→ 保存 DocumentChunk
```

索引块会保存课程 ID、课次 ID、父块 ID、时间范围和 `source_segment_ids`，保证检索结果可以回链到原始逐字稿和播放器时间点。

## 3. 父子块切分

### 子块

子块是检索和排序的基本单位。它应包含一段相对完整的课堂表达，保留定义、条件、例子或结论中的完整关系。

子块主要用于：

- BM25 检索；
- 向量检索；
- Cross-Encoder 重排；
- 精确引用和时间定位。

### 父块

父块是一段更完整的课堂上下文，通常包含同一主题下的多个子块。

父块主要用于：

- 给大模型提供完整上下文；
- 补回定义、原因和例子之间被切开的关系；
- 避免模型只看到一句不完整的逐字稿。

检索时先找子块，问答时根据 `parent_id` 扩展父块。最终引用仍使用子块的时间和 `source_segment_ids`。

切块时重点保护：

- 语义停顿和说话人变化；
- 定义、原因、例子、结论；
- 数字、单位、公式和专业术语；
- 否定词和条件限制。

## 4. 用户问题处理

用户提问后，系统先校验用户、课程和课次范围，确保只在授权数据内检索。

之后对问题进行归一化和查询改写：

- 去掉“请问”“帮我解释”等无关前缀；
- 保留专业术语、数字和否定词；
- 对“并且”“另外”等连接的多意图问题进行拆分；
- 查询改写失败时使用原问题。

系统不会只使用改写后的问题，而是保留原问题、改写问题和子问题进行多路召回，避免改写丢失关键信息。

## 5. 混合召回

ClassAgent 使用 BM25 和向量检索两条召回链路。

### 向量检索

用于处理：

- 同义表达；
- 口语化提问；
- 词面不同但语义相近的问题。

### BM25 检索

用于处理：

- 专业术语；
- 数字和位宽；
- 公式和英文缩写；
- 精确短语和否定词。

两路结果先分别召回，再用 RRF 融合：

```text
BM25 结果 + 向量结果
→ RRF 统一候选排序
```

当前问答默认最终返回 8 个块，候选阶段会先取得更多候选，再进行重排，避免过早截断导致目标内容无法进入精排。

## 6. Cross-Encoder 重排

混合召回得到候选后，系统使用 DashScope `gte-rerank-v2` Cross-Encoder 对“问题 + 候选内容”重新判断相关性。

流程是：

```text
混合召回候选
→ Cross-Encoder 精排
→ 来源去重
→ 限制同一父块返回数量
→ 选出最终 Top-K
```

Cross-Encoder 服务不可用时，系统回退到本地重排，使用 BM25、关键词覆盖率和短语匹配，保证检索仍可用。

## 7. 父块上下文和答案生成

最终命中的是子块，但模型回答使用对应的父块上下文：

```text
子块命中
→ 查询 parent_id
→ 读取父块
→ 父块作为模型上下文
→ 子块作为引用依据
```

大模型只能依据检索到的课堂片段回答，并输出引用 ID。后端会校验：

- 引用 ID 是否真实存在；
- 引用是否属于本次检索结果；
- 课程和课次是否属于当前用户；
- 答案是否引用了未提供的内容。

没有足够证据时返回资料不足，而不是补充课堂之外的常识。

## 8. 权限和故障降级

权限过滤在检索前执行：

```text
用户 → 课程归属校验 → course_id/lesson_id 范围过滤 → BM25/向量召回
```

用户不能通过查询词、课次 ID 或父块 ID 访问其他用户的数据。

故障时采用降级策略：

- 查询改写失败：使用原问题；
- 向量服务失败：使用 BM25；
- Cross-Encoder 失败：使用本地重排；
- 没有有效候选：返回资料不足。

## 9. 当前评测结果

当前主要区分两类指标：

### 课次级召回

判断正确课次是否进入结果。1000 条测试结果：

```text
Recall@5 = 0.9820
```

### 子块级召回

判断目标逐字稿子块是否进入最终结果。排除对抗问题后的 900 条测试结果：

```text
Recall@5  = 0.6800
Recall@10 = 0.8856
```

同一批问题的候选召回结果：

```text
Recall@20 = 0.9667
```

这说明正确内容大多可以进入候选池，但部分内容在最终 Top-5 或 Top-8 排序中靠后。当前主要优化方向是精排、数字条件匹配和最终结果截断。

## 10. 一句话总结

ClassAgent 的 RAG 采用“子块高召回、父块补上下文、混合检索、重排筛选、引用可追溯”的方案：先用 BM25 和向量检索找到候选子块，再用 Cross-Encoder 排序，最后扩展父块交给大模型回答，并通过权限和引用校验保证答案只来自用户有权限的课堂内容。
